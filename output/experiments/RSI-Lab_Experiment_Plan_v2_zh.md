# RSI-Lab 实验方案 v2

本方案整合双层智能体设计与必要的实验实施细节，主要描述后续正式研究。当前分支已实现固定 CDK2 / AutoDock Vina 的探索性 Lab/Meta pilot，并完成一次含两组配对验证的真实闭环；实现与结果见[运行说明](../../docs/live-agentic-study.md)和[验证记录](../../docs/validation-v1.md)。本文更大的试验规模、额外预测工具和统计比较仍是规划，不能视为已经执行。具体正式参数、预算及数值门槛须在相应实验前冻结。

**一、研究目标与实验范围**

RSI-Lab 在固定计算评测协议与资源预算下，自主规划化合物筛选，并根据跨轮次执行经验改进自身的工作机制。Lab Harness 根据公开历史证据和新增计算结果，决定候选优先级、工具组合、计算投入及停止时机；Meta-Harness 自动诊断运行问题，提出提示词或代码修改，经独立验证后发布。

研究目标是减少对人工筛选策略和反复手动调优的依赖。系统仍保留统一的数据有效性检查、工具接口约束、资源上限和外部评测规则，使不同方法与版本能够公平比较。

本项目采用纯计算实验（in silico），不包含湿实验闭环。正式方案可将已有 IC50 作为公开输入；本次 r3 探索性闭环使用不含活性数值的 structure-only cohort。新增证据来自实际运行的预测、结构计算及计算验证。计算验证通过只说明候选满足所选协议，不能等同于真实生物活性、药效或新药发现。

三个研究问题分别是：

| 问题 | 主要对照 | 需要回答的内容 |
|---|---|---|
| RQ1：轮内自适应是否有效？ | 固定 Harness agent H0 vs 固定流程、成本规则 | 自主规划能否改善筛选质量或计算效率 |
| RQ2：跨轮次机制改进是否有效？**主问题** | 最终冻结的改进版 H* vs 初始固定版 H0 | 在相同底座模型、公开历史和资源上限下，修改 Harness 是否带来额外收益 |
| RQ3：收益来自什么修改？ | H* vs 撤销具体修改的版本 | 哪些证据处理、失败反馈或决策检查改进产生了作用 |

PABLO 提供了分层探索、策略生成、执行反馈和策略记忆的参考；它同样保留预算、有效性检查与去重。RSI-Lab 将这些思想用于固定候选池的多工具筛选，并增加跨 campaign 的 Harness 修改与验证。

第一阶段固定一个蛋白靶点、一个候选池生成规则和一组工具，冻结所有底座模型及预测模型权重。模型训练、池外分子生成和第二靶点迁移均不纳入核心实验。

**二、纯计算环境与数据构建**

**靶点选择。** 从 ChEMBL 与 BindingDB 审查研究充分、序列明确、具有足够不同化合物 IC50 记录的靶点。选择依据包括 assay 可比性、结构输入可用性、工具支持和计算成本；不得依据哪一个靶点让 RSI-Lab 获胜来选择。当前 v1 pilot 已固定 CDK2 / 1DI8；后续正式研究仍须独立登记靶点与结构选择依据。

选定后记录物种、序列、构建体、突变、修饰、伴侣蛋白、结合位点和 receptor 来源。计算输入与实验测定涉及不同蛋白状态时，必须解释建模近似；不能只因名称相同就合并不同构建体的证据。

**清洗与证据保留。** ChEMBL 作为主来源，BindingDB 可补充覆盖。保存数据库版本、获取日期、原始记录 ID、文献、assay 条件和处理脚本。端点以 IC50 为主，统一单位并检查值域；Ki、Kd、细胞增殖 EC50 等不直接混入同一 IC50 排序。ChEMBL 的靶点置信标记可辅助筛选，但不能保证不同 assay 条件一致。[ChEMBL 数据说明](https://chembl.gitbook.io/chembl-interface-documentation/frequently-asked-questions/chembl-data-questions)

- 规范化化合物标识、盐形式处理和立体化学；去除重复候选，保留全部可追溯原始测量。
- 精确关系“=”的正值用于主排序；“>”“<”等记录保留为区间证据，不转成伪精确值。
- 同一可比 assay 条件下的重复测量可在 log 尺度汇总；跨 assay 的差异保留为冲突或分层证据，不简单取全局均值。
- 候选池包含较强、较弱及不同骨架的分子。记录纳入/排除数量，冻结抽样规则；计算失败的难例不能在正式结果中事后删去。
- 为 IC50 基线定义统一的可比记录选择、汇总、缺失处理与并列排序规则，同时向所有方法开放原始证据。

**数据与 campaign 划分。** 将用于新计算的候选划分为 pilot、development、validation 和 final campaigns。相同分子不跨集合；尽量按 scaffold/相似性簇分组，并将同源文献记录放在同一组。若结构簇与文献关系使联合隔离不可行，应报告重叠情况并限制泛化结论。

这里隔离的是用于开发、版本选择和最终评价的新计算反馈。公开 IC50 与已有结果仍然开放；该划分不能消除模型预训练重叠，也不能被描述成隐藏 IC50 的预测测试。

**工具箱。** 优先接入少量功能明确的工具，实际组合由 pilot 决定。

| 工具类别 | 候选实现 | 用途及输出 |
|---|---|---|
| 公开证据与基础特征 | 数据查询、分子特征、结构簇分析 | 已知测量、来源、相似性与低成本特征 |
| 相互作用预测 | Boltz-2、Nesso-1 | 额外预测信号及工具支持的结构/置信信息 |
| 固定计算验证 | docking/rescoring 与 pose-validity checks | 按共同协议生成评分、有效性及失败状态 |

Boltz-2、Nesso-1 是候选预测工具，不预先宣称其在当前靶点上的精度或速度优势。记录每个模型的版本、权重、输入要求和各输出字段的单位、方向与适用含义；不能将不同字段直接混用为同一种亲和力。具体接口以官方文档和 pilot 输出核对。[Boltz](https://github.com/jwohlwend/boltz)、[Nesso](https://github.com/recursionpharma/nesso)

**三、系统架构与自主决策边界**

| 层次 | 职责 | 可变化内容 |
|---|---|---|
| Lab Harness | 规划和执行计算实验，管理证据，排序并提交 shortlist | campaign 内的策略、候选顺序、工具选择、预算分配和提前停止 |
| Scientific Memory | 保存已知记录、新结果、失败、成本、冲突与未决问题 | 运行状态持续更新；派生结论必须关联证据 |
| Meta-Harness | Diagnose → Improve → Validate & release | campaign 之间修改 Harness 提示、代码和更新规则 |
| Docking Evaluator | 执行独立 AutoDock Vina CPU 对接、计量资源、核验姿态并汇总能量 | 软件版本、两个种子和姿态选择规则在正式比较中固定 |

Lab Harness 可参考 Explorer–Planner–Worker 分工：Explorer 关注覆盖不足的候选，Planner 制定计算策略，Worker 执行请求；也可使用单一规划 agent 加工具执行器。该角色划分是参考实现，不是研究结论成立的前提。主比较中 H0 与 H* 从同一初始实现出发。

Scientific Memory 至少区分原始观测、模型预测、计算验证结果和假设。每条用于排名的关键事实链接到来源或工具输出，记录矛盾与不确定性。策略注册表可保存尝试次数、实际成本、失败类型及收益，支持在线决策；原始结果不能被摘要覆盖或改写。

可由 agent 调整的内容包括内部筛选阈值、实验优先级、工具调用顺序和停止判断。固定的内容包括候选池资格、输入合法性检查、预算计量、评测协议及最终输出规则。agent 可以提前结束；资源耗尽时由外部执行层停止新请求，并按事先定义的提交规则收尾。

H0 允许在 campaign 内反思、换策略和更新记忆；固定的是系统提示、代码及机制更新规则。H* 的区别是这些机制经过跨 campaign 修改和验证。所有模型权重保持不变。

**四、Docking 评估器与计算验收协议**

当前 v1 固定使用独立 AutoDock Vina 1.2.7 的 Vina 评分函数，在 CPU 上完成对接。Meeko 准备配体 PDBQT，并将输出姿态映射回原分子，供 PoseBusters 检查。Controller 分别登记在线筛选和提交后终评的请求、成本及原始结果。正式比较前冻结受体、结合位点、配体准备规则、软件与权重版本、搜索参数、姿态检查、能量阈值、超时与重试规则。[AutoDock Vina 基础对接](https://autodock-vina.readthedocs.io/en/latest/docking_basic.html)、[PoseBusters](https://github.com/maabuu/posebusters)

对候选 x 执行两个固定种子 17、43。每个种子只选 Vina 输出的第一姿态，记录其有效性，以及 PDBQT 中 `REMARK VINA RESULT` 的 affinity（kcal/mol）。两个所选姿态均有效且能量有限时，q(x) 为两个能量的中位数，越低越好。缺失种子、准备失败、超时或姿态无效使 q(x) 缺失。正式阈值 τ 的判定公式如下。

`v(x) = 1{两个所选姿态均有效且 q(x) ≤ τ}`

在 development 阶段使用参考化合物、能量分布和重复稳定性选择 τ，记录依据后冻结。输入示例中的 −7.0 kcal/mol 尚未校准。pilot 同时报告姿态覆盖和能量，正式阈值须在查看 final 结果前确定。

pilot 可对有参考姿态的共晶配体做 redocking，检查 receptor、位点和准备过程。没有实验参考姿态的普通候选，不将 native-pose RMSD 作为通过条件。Pose 有效性和打分结果仍是计算性质，不构成生物活性真值。

v1 固定每种子执行一次，失败占用名额且不自动重试。后续扩大研究规模时，在正式运行前冻结失败处理与复核预算。

- 输入不合法、准备失败或姿态无效，记录对应终态，不通过无限重试寻找有利结果。
- 临时基础设施故障仅允许协议规定次数的原参数、原种子重试；所有成本计入。持续 OOM 或达到协议超时后保留失败终态。
- 在线资源不足造成的未启动或截断请求记为“未评估/未完成”，与完成协议后的验证失败分开。
- 终评使用共同额度补齐名单内未完成的协议执行；完全匹配的已完成结果可复用。最终 v(x) 不依赖某个方法提交前剩余多少预算。
- 系统性环境故障可使受影响的比较块作废并按统一规则重跑；不得只重跑不利于某方法的结果。

主实验允许所有方法将 verifier 当作一个公开、付费的在线工具。已完成的结果可用于决策，因此研究对象是有限预算下对固定计算目标的搜索和证据利用。终评补齐相同协议并不构成独立生物学验证；若要检验对评分器的适应程度，另设冻结后的第二构象/第二协议检查，单独报告，不回调主结果。

**统一官方结果。** `select-final` 读取现有归档，固定输入及协议下的每个分子使用同一 q(x)/v(x) 判定规则。若将来开展跨分支冲突复核，应在正式运行前登记复核条件、统一执行环境、择用记录规则及成本上界，并分别保留初始与复核证据。

**五、Campaign 流程与开放证据管理**

一个 campaign 定义为固定靶点 T、候选池 X、起始公开证据快照 D0、工具目录、资源上限 B、shortlist 大小 k 及验收协议 V。每个方法在该任务上运行一个独立实验分支。

**正式 docking 名单。** `select-final` 根据清单中已完成且采用兼容冻结协议的 live Lab 运行核验原始 batch、产物和姿态检查，计算在线及 terminal 作业中每个合格化合物的双种子 docking 能量，另行记录失败作业与未对接候选。清单格式为 `{"schema_version":"lab_docking_selection_input_v1","threshold":-7.0,"runs":["runs/completed_live_lab"]}`，路径相对清单自身。阈值单位为 kcal/mol，示例值尚未校准。正式筛选接受独立 Vina 的 live 归档，历史 GNINA、回放和调用者提供的评分表均不满足该输入契约。最终保留所有 q(x) ≤ τ 的化合物，按冻结 registry 的 `canonical_parent_identity` 去重，历史单结构输入回退到 `canonical_smiles`；同一 parent 的多个 prepared state 不能重复计数，冲突记录被拒绝。至少须有 100 项，少于 100 项时报告缺口。当前单次 CDK2 pilot 从 20 项中提交 5 项，分别报告姿态覆盖、能量和成本。


1. **初始化。** 导入相同 D0、候选清单和规范化初始记忆，包括公开 IC50、文献/assay 信息和截止时点前已完成的工具结果。设置相同可用接口及计量规则。
2. **自适应执行。** Lab Harness 读取证据与剩余预算，提出计算请求；evaluator 检查请求、实际执行并返回结果、失败与成本；Harness 更新证据、候选排序及下一步策略。
3. **过程记录。** 保存每次决策的简短理由、引用证据、工具请求和结果；在预先固定的预算检查点保存当时的临时名单。提前停止的运行在后续检查点沿用最终名单。
4. **停止和提交。** agent 自主停止，或达到外部资源上限。提交 k 个不同的池内候选、排名、证据及未决问题，并锁定文件与时间戳/hash。始终维护可提交的当前名单，避免预算耗尽后额外付费生成未计入预算的报告。
5. **统一终评。** evaluator 对锁定名单及预登记检查点的候选补齐验收；新增终评结果不再反馈给本次筛选，不允许替换候选。缺项、重复或池外项按相应位置失败处理，分母保持 k。
6. **归档。** 汇总该比较批次的轨迹、结果、成本与版本记录；开发批次可进入后续 Meta 改进，final 批次只用于本次最终分析。

比较开始前，为所有最终名单与预登记检查点候选并集预留终评额度；按候选数量上界、R、允许重试次数与单次硬超时估算成本上界。若计划报告精确 EF，还需覆盖整个候选池。资源不足时在执行前统一减少检查点或实验规模；若执行中全局终评额度不足或基础设施中断，标记该比较批次未完成，补齐前不作完整方法比较，也不把尚未评估的候选计为验证失败。达到事先规定的单候选超时则仍按协议失败处理。

**公开数据与分支隔离。** 同一比较批次从同一 D0 启动，各分支立即可读自身实际产生的新结果，但不读取其他分支在本批新产生的结果；批次结束统一归档公开。这样后运行的方法不会因物理调度顺序获得免费新增证据。下一批比较从更新后的共同快照开始。若研究全局实时共享实验室，应另设共享场景，不能与独立方法对照混合解释。

H0 与 H* 在最终比较中获得相同公开 development/validation 原始结果、历史记录与规范化初始记忆。不同 Harness 可按自身机制整理或摘要这些材料，消耗计入预算；不向 H* 独享额外缓存、私有实验结果或预先计算的派生答案。

**已知结果与新增收益。** 不隐藏已有验收结果。优先构造完整验收输出尚未产生的新候选池，并分别统计：D0 已知通过的候选、本次提交前新增确认通过的候选，以及提交后才经统一终评确认通过的候选。若所有候选验收结果都已知，该池适合评价证据利用，不能用于声称新增计算带来了发现收益。

**六、Meta-Harness：修改、验证与自动发布**

先建立一个可以完整运行的 H0，再进行跨 campaign 改进。自动化从初始实现和提示模板出发，研究期间不由人工逐轮替 agent 调提示词或筛选赢家。

**Diagnose。** 在 development campaigns 上检查计算浪费、证据冲突、重复失败、无依据陈述及决策问题，输出结构化诊断：问题、轨迹证据、可能原因、预期影响。

**Improve。** 每轮提出一个小幅、版本化 patch，说明修改位置、预期收益和可能退化。允许修改证据组织、记忆更新、失败恢复、工具调度、决策检查及提示模板；不修改模型权重、数据划分、候选池、预算器、外部评分协议或分析脚本。具体分子的事实保存在科学记忆，不硬编码为通用机制中的答案。

**Validate。** 先进行接口、日志和预算约束等基础检查；通过后，候选版与当前发布版在本轮新的 validation pool 上，从同一 D0 和初始记忆配对运行。固定相同 seeds、硬件和资源上限，所有失败运行纳入统计。未通过基础检查的 patch 也记录在修改尝试总数中。

**Release。** v1 的 Meta gate 使用预登记的配对 validation 运行。每个实验臂分别计算双种子姿态有效的候选数，以及这些候选 q(x) 的条件均值。任一对的有效候选数下降，或任一臂的能量均值缺失，均不能采用候选版本。令 G_E 为父版本能量均值减候选版能量均值后跨配对的平均值，G_E 为正表示 docking 能量改善。令 G_C 为有效候选数的平均增加量。

| 发布路径 | v1 工程判断条件 |
|---|---|
| 质量提高 | G_C = 0 且 G_E ≥ 0.1 kcal/mol，或 G_C ≥ 0.2 项且 G_E ≥ −0.1 kcal/mol |
| 节省 tokens | G_E ≥ −0.1 kcal/mol，且验证运行的 tokens 至少减少 10% |

这些门槛用于判定版本能否进入下一轮开发。正式科学比较另行预登记阈值、样本量和分析方法，并报告逐池效应、姿态覆盖、失败及实际成本。

下一轮基于实际发布版本继续运行 development，并可吸收前轮已公开经验；版本选择使用新的 validation pool。若不得不重复使用验证池，应记录其自适应复用，不再声称它对后续修改独立，并降低发布证据的强度。v2 首选预留不同验证池、限制尝试次数。

所有 patch 的提议、基础检查、验证、拒绝和发布均留档，未发布版本的成本也计入。人工如为基础设施排错作出修改，应标明人工干预、受影响版本及是否需要重新开始比较，不能混入自动改进收益。

达到轮次或资源上限后，将最后实际发布版记为 H* 并冻结；最终测试不再提出、选择或发布修改。无合格 patch 时 H*=H0，应报告未发现稳定改进。只有一次成功发布时，结论限于一次机制改进，不能据此证明持续递归收益。

**七、基线、消融与鲁棒性实验**

所有方法获得相同开放输入、工具访问权限和资源上限；某一基线按其定义只选择使用其中部分工具。相同预算指相同可用上限，不要求随机、IC50 等方法花满资源。基础模型版本与模型权重在比较期间固定。

| 方法 | 预先冻结的策略 | 目的 |
|---|---|---|
| Random | 从池中均匀抽取 k 个，记录 seed | 随机参照 |
| IC50 ranking | 按可比 IC50 汇总值排序，使用固定缺失及并列规则 | 公开实测证据的简单利用 |
| Single predictor | 只新增调用一个选定预测器；按固定 scaffold 轮转/随机顺序访问候选，预算内执行 | 单预测器参照 |
| Fixed two-stage | 廉价评分覆盖全池，再对固定前 m 个使用较昂贵工具，按第二阶段结果排序 | 人工固定计算流程参照 |
| Simple cost-aware rule | 按冻结的潜在收益/预计成本公式选择计算并更新数值，不使用 LLM 改写公式 | 简单成本规则参照 |
| Fixed-Harness agent H0 | 允许在线规划、反思和记忆更新，禁止跨 campaign 修改机制 | 核心对照 |
| RSI-Lab H* | 使用经过 Meta 验证发布后冻结的 Harness | 核心方法 |

Single predictor 的访问顺序不按其尚未计算的分数决定。Fixed two-stage 的第一阶段可以是公开证据/基础特征评分，或 pilot 证明能覆盖全池的低成本预测器；第二阶段工具、m 与预算分配提前确定。两阶段的全部计算计费，必须确认第二阶段实际执行并影响排序；若退化成同一单模型策略，应合并或重设对照。

Simple cost-aware rule 的可执行起点是直接调用固定 verifier：用公开 IC50 的效力百分位作为潜力信号，除以 pilot 成本表给出的预计验证费用，优先验证比值较高的未完成候选；并列按固定 ID 排序。已完成结果更新候选状态，公式保持不变。采用其他成本规则时须在正式比较前写明公式和缺失处理，不能在 final 结果上挑选。

该规则使用“越强越高”的效力百分位；缺少可比 IC50 时默认潜力值为 0，并列按 ID，预计验证费用必须为正。提交时先列已完整验证通过者并按 q(x) 从低到高排序，再列未完成验证者并按公共 IC50 fallback 排序，最后为已完整验证失败者；各层并列规则固定，补齐至 k 个。部分种子结果不会被算作完整通过。

对于 Single predictor / Fixed two-stage，已有且符合版本要求的公开模型结果免费复用。默认将可用主评分项按预定方向排序，缺少评分的候选按公共 IC50 fallback 追加，直到 k 个；不同分数不未经校准直接混合。固定名单补齐规则不使用事后验收结果。H0/H* 可自行整合相同证据，但也必须在提交前完成名单。

若 D0 含有同协议验收或其他新增公开结果，额外设置 **Best available evidence**：不进行新计算，按冻结的公开证据规则排序。建议优先已验证通过者，再排序尚未验证者，最后为已验证失败者；组内使用统一评分/IC50 fallback。其规则与 IC50 基线完全相同时合并展示。它用于检查新增计算是否超过直接利用已有结果。

**消融。** 围绕实际发布 patch 构建撤销版本：撤销证据来源/冲突处理修改、失败分类/恢复修改，或决策检查修改。原始工具结果记录、共同预算器和有效性检查不随消融删除。没有对应改动时该消融不适用；无法独立撤销时报告修改间依赖，按修改组撤销。优先完成最关键的一项，再根据资源增加其余项。

所有消融在查看 final 结果前确定，并与 H* 使用同一 D0，作为同一比较批次执行。若 final 结果已经公开成为新历史，后续消融需与 H* 在新 D0 下重新配对，不能直接复用旧 H* 数字。

**鲁棒性。** 优先增加独立候选池，其次测试低/中/高资源上限及指定工具不可用。工具失效设置、受影响调用序列和成本处理在比较前固定，并对配对方法一致。第二 receptor、第二评分协议或第二靶点属于扩展；选择依据提前确定，其结果不用于回调主方法。

**八、指标、统计分析与结论判定**

主指标是 shortlist 的计算验证通过率：

`Q = VPR@k = (1/k) × Σ[x in shortlist] v(x)`

名单缺项、重复或池外项占用的位置计为失败；协议执行后仍无法验证的候选按预定失败规则处理，并单列原因。主对比固定为 `ΔQ_final = Q(H*) − Q(H0)`，报告百分点差、每池结果和不确定性。

| 指标 | 定义与用途 |
|---|---|
| VPR@k 与相对 H0 的差值 | 主终点；区分跨轮次机制改进收益 |
| 相对最佳已有证据基线的差值 | 检查是否仅重复已有高分结果 |
| 新确认通过数 | D0 无完整验收结论，最终名单中本次新确认通过的不同分子数 |
| 在线新确认通过数 | 提交前完成完整协议、当时判为通过且在统一官方表中仍通过的新增不同分子数；不含提交后才完成者；另报在线判断与官方结果的冲突数 |
| 连续评分与有效性 | 分别报告 q(x) 分布、有效姿态比例和失败比例；不只在成功子集上比较平均分 |
| 质量—预算/费用曲线 | 在预定检查点保存名单，全部冻结后统一评价；不能向早期决策反馈未来结果 |
| 在线确认效率 | 在线总成本 / 在线新确认通过数；零通过时单列，分母不随意加常数 |
| 名单确认总成本 | 在线成本加其所需终评成本，除以名单新确认通过数；明确共享计算的成本分摊 |
| 执行可靠性 | 完成率、有效工具调用比例、失败/重试成本、重复计算、预算越界 |
| 证据质量 | 关键事实具有可核验来源且支持其表述的比例，另报无依据陈述 |
| 候选多样性 | scaffold 数量、相似性分布，作为描述性结果 |

完整池的通过率为 `p_pool = Σ[x in X]v(x)/N`，则 `EF@k = VPR@k/p_pool`。精确 EF 需要全池固定验收；仅在所有方法与检查点名单冻结后补齐，并单列评测成本。预算不足时，用预先抽样的随机参考名单估计随机表现，报告差值和不确定性；基于估计分母的比值必须标为估计 EF，不能称作精确富集度。分母为零时 EF 未定义。

证据检查包括自动校验来源 ID/链接，以及对各方法等量、按固定规则抽取的关键陈述进行盲化人工复核。人工复核仅用于结果审计，不反馈本轮 agent 决策。LLM 评分可作辅助，不能单独作为筛选质量或证据真实性的依据。

统计分析以候选池/campaign 为主要比较单位，同一池内 seeds 为嵌套重复。先在池内平均，再计算方法间配对差值；候选分子数、调用次数或同池重复不能充当独立样本数。候选池存在重叠时报告重叠并调整独立性主张。

建议起步采用 3 个独立 final pools、每池 2 个 seeds，作为探索性比较，展示逐池效应和范围。正式扩大规模时，依据 pilot 方差与最小有意义效应规划池数；可按池进行配对/聚类重采样，但少量池的区间仍不稳定，不能靠增加同池 seeds 替代新增池。

最终质量提升仍以 H*−H0 为主分析；质量在容差内且成本下降作为预先登记的第二类结果。样本充分时，按预定效应门槛、质量差与成本节省的联合/多重性校正区间判断；不能看完结果后任选容易通过的检验。样本不足时只报告观察到的效应，不将 validation 发布成功当作显著性或非劣证明。

IC50 一致性用于描述证据利用，不作为隐藏活性预测成绩。若质量没有提高但失败成本降低，应报告该效率结果；若没有稳定收益，保留负结果，不更换主指标或阈值。

**九、计算预算与完整成本核算**

Vina pilot 在计划使用的 CPU 环境测量冷启动、运行时间、CPU 消耗、失败比例和 LLM 费用。正式配对使用相同 CPU 配额与并发限制。另行引入的 GPU 预测工具按设备占用时间单独计量。

预算向量包含 GPU 时间、CPU core-hours、LLM token/API 费用及总时长。必要的最大调用数用于防止无限循环，不代替 agent 的自主提前停止；数值由 pilot 确定。若直接验证全池在给定预算内已轻易完成，需在正式比较前统一调整 N 或预算，使任务仍存在计算选择问题，并保留调整依据。

所有失败、重试、准备过程、提示/上下文构造及报告生成消耗都按相同口径记录。公开历史缓存对各方法同等可读；同一分支重读已知结果只计读取开销。跨方法复用本批新结果以节省真实计算时，必须标记为重放，并按预先定义的独立执行成本扣除逻辑预算；另报真实物理成本，不把缓存带来的免费计算宣称为算法效率。

费用账本分为：

`C_total = C_setup + C_online + C_meta + C_eval`

- C_setup：数据准备、共同工具部署、pilot 和基础实现成本；各方法专属基线调优也记录。
- C_online：正式运行中的预测、在线 verifier、CPU 工作与 LLM 消耗。
- C_meta：修改提议、诊断、额外 development、基础检查和所有 validation 成本，包括拒绝版本。
- C_eval：提交后名单/检查点评价、随机参考或全池验收等分析开销。在线 verifier 已计入 C_online，不重复记入。

各类别互斥，开发、验证和 final 的每次调用均有唯一归属。人工工时单列，不在无约定的情况下折算成计算费用。对正式方法对比报告相同在线资源上限下的质量，同时报告完整实际总成本；对可复用 Harness 再给出 `C_online + C_meta/M` 随假设部署 campaign 数 M 的摊销结果，明确这是成本情景而非已实现节省。

统一终评对不同名单的重叠候选去重执行。方法级成本报告可同时给出独立运行时的等价验收成本和整批去重后的实际成本，避免因哪个方法先执行而改变费用归属。

**十、实施阶段、规模与交付物**

下表是第一轮可行性与资源规划示例，不是已完成实验，也不承诺统计功效。所有正式规模在 pilot 后结合可用数据、GPU 配额和截止时间确定。

| 阶段 | 建议起点 | 完成条件 |
|---|---|---|
| P0：可行性 | 约 20–30 个候选，逐项检查工具及重复稳定性 | 靶点输入可用、成本可测、验收定义可解释 |
| P1：基础闭环 | N=100、k=10；至少两组 development campaigns | H0、基线、预算器、日志及名单冻结可以完整运行 |
| P2：机制改进 | 可从最多 3 轮、每轮 1 个 patch、2 个 validation seeds 估算资源 | 总修改预算与发布规则先冻结；每轮新 validation pool |
| P3：核心比较 | 7 方法 × 3 final pools × 2 seeds | 42 个计划评估单元，主对比 H* vs H0 |
| P4：消融 | 优先 1 项实际修改撤销；同样的池与 seeds | 额外 6 个评估单元；完整三项时为 18 个 |
| P5：扩展 | N=300、k=20；更多独立池或其他资源条件 | 主闭环完成且数据、算力允许 |

若 Best available evidence 与 IC50 不同，P3 增加 6 个单元。确定性基线在相同输入下无需重复执行或重复计作独立样本。以上运行数不包含 pilot、development、验证和终评开销。

按示例，两个 development 池、三个 validation 池、三个 final 池均为 100 个不同分子，加约 30 个 pilot 分子，理想情况下需约 830 个候选及足够不同结构簇；当前尚未确认可满足。数据不足时优先缩小池或改进轮数，不能用重叠分子池伪装独立重复。

工作安排可按四阶段推进：先完成数据/工具 pilot；随后完成 H0 与基线；再进行受预算约束的 Meta 改进；最后冻结版本完成对照、消融与分析。若按四个工作周安排，各阶段暂对应一周，实际进度取决于资源与课程截止时间。

两人协作可分别负责“数据、工具、评估器与成本”和“Harness、Meta、基线与调度”，共同审核协议冻结表及最终分析。

交付物包括数据 manifest、清洗记录、冻结协议、工具适配器、H0/H* 代码及提示、完整 patch/release 历史、运行轨迹、名单与报告，以及可重复执行的分析脚本。推荐目录：

```text
data/manifest.csv                 # 候选、目标、assay、来源、分组
configs/protocol.yaml            # 工具、评分、预算、种子、失败与发布规则
harness/                        # 初始与发布的工作机制
meta/                           # 诊断、修改、验证、发布
tools/                          # 计算工具与 verifier 适配器
baselines/                      # 冻结的基线规则
releases/                       # 提议、差异、验收、拒绝/发布记录
runs/<batch>/<pool>/<method>/    # 轨迹、成本、证据、名单与报告
analysis/                       # 配对分析、图表与结果审计
```

计算记录至少包含 batch/campaign、方法、Harness 版本、分子 ID、工具及权重版本、输入/参数 hash、seed、资源消耗、状态、输出 hash 和 evidence ID。名单记录提交时间及 hash，保证事后评价不会反向改变选择。

**十一、参数冻结表与最终报告要求**

| 参数/规则 | 确定依据 | 最晚冻结时点 |
|---|---|---|
| 靶点、构建体、数据纳入及分组 | 数据可比性和工具兼容性 | 正式 development 前 |
| 工具版本、输入准备、成本计量 | pilot 的可用性与实际成本 | 正式 development 前 |
| 独立 Vina 双种子协议、q、τ、失败规则 | 固定种子 17、43，双有效姿态能量中位数，参考化合物和重复稳定性用于确定 τ | Meta 验证和主比较前冻结 |
| 池大小 N、名单 k、各资源上限 | 数据量、单次成本、任务难度与总配额 | 对应正式比较开始前 |
| 基线策略、访问顺序、m 与 fallback | development 或单独的基线调优任务；成本留档 | final 前 |
| δ_gain、δ_NI、γ、可靠性门槛 | pilot 波动、最小有意义差异及成本目标 | 第一轮正式 Meta 验证前 |
| 修改轮数、候选数量、Meta 预算 | 总资源和验证池数量 | 第一轮 Meta 改进前 |
| final 池数、seeds、主次指标与统计规则 | pilot 波动和研究问题 | 查看任何 final 结果前 |
| H*、消融版本及稳健性条件 | 已发布 patch、实际机制与预先设计 | 对应 final 批次执行前 |

冻结之后的必要修订须记录原因、影响范围和是否重跑；不得在同一结果表中混合评分或成本口径不同的版本而不标注。

最终报告至少包含：各方法的逐池通过率和 H*−H0 差值；质量—成本关系；新增确认与复用历史的拆分；修改与拒绝轨迹；实际 patch 的消融；完整预算账本；成功与失败案例；数据重叠、评分器局限及小样本不确定性。所有已运行的预登记对照和失败版本均有记录。
