RSI-Lab 系统设计：通用内核、领域包、计算任务与运行中修复

版本：2.1 · 日期：2026-11-08 · 状态：目标设计规格，待逐项实现与验证。当前代码边界见 核心实现说明；本文不表示全部能力已交付。

本版将系统拆为 rsi_lab、rsi_domains 与计算任务 task，并将 Meta 的主路径改为任务进行中的发现、调查、修复、小范围验收、发布与续跑。预先授权范围和预算内的操作自主完成；冻结科学要求保持不变。P4 验收实际修复和成功继续任务，独立收益比较是后续可选研究。

v2.1 明确 Meta 对发现问题负责：独立读取运行事实，在没有 Lab 报错、没有规则告警时也持续巡检；主动追查目标偏离、静默数据错误和能力缺口，自行取证并跟进处理。周期巡检、停滞诊断、覆盖记录和反证要求见 §7.1–7.6。检测主动性以提前发现和调查闭环衡量，不以告警数或修改数衡量。

v2.1 同时将开源 Codex harness 的源码修复纳入主闭环：Meta 可自主发现执行层问题，在 task 预授权范围内修改指定 fork，编译并验收候选，切换本运行使用的 Codex 版本后继续任务；失败自动撤销候选或回退。该能力使用同一 ChangeEngine，具体绑定、进程切换与恢复契约见 §11.6；它是必须实现和验证的目标能力，当前文档更新不表示运行代码已具备此能力。

本文取代 v1.0 的默认配对实验发布门槛、T3 整体禁用及只在下一运行启用的限制；保留不可变事实、精确交付、预算守恒、外部效果恢复和版本追踪要求。本文是完整的目标设计，不报告新运行结果，也不表示代码已按此重构。本发布副本仅包含目标设计，不分发既有实验记录、结果快照或原始模型对话。

Scientific Memory 修订：新增以研究问题组织的持久科研状态，连接来源、判断、研究行动、方法经验与决定。按问题读取支持/反证与未结工作，来源变化和新增证据均触发有界复核；观察卡与引用统一交付。主契约见 §10.3，实体、API、预算、迁移和 SM01–SM20 验收同步更新；通用机制不依赖化合物候选或单一评分。

第一部分：三层解耦

A.1 三层的责任与依赖方向

系统拆为通用内核 rsi_lab、领域包 rsi_domains 和计算任务 task。Lab 与 Meta 是内核承载的执行角色；领域包提供科学能力；task 指定这一次要完成什么、用哪些输入、满足哪些条件。

层 负责 不应包含
rsi_lab 状态、调度、预算、事件与证据、外部调用、上下文、能力加载、变更验收与恢复 化合物结构、靶点名称、领域分数公式、具体科学阈值、特定任务的完成数量
rsi_domains.<domain> 领域数据类型、输入校验、身份规范化、计算与分析适配器、结果解释、领域验收规则 通用调度器实现、全局事件存储、绕过内核的调用与计费、当前任务的硬编码配置
task 科学目标、输入与协议、所选领域能力、计算依赖、冻结要求、预算与 Meta 授权、产物及完成判据 复制一套内核、隐含的全局状态、在提示词中覆盖冻结协议

依赖方向固定：领域包实现内核定义的接口；task 通过配置引用内核与领域能力。rsi_lab 不导入具体领域包，安装内核并运行领域中立 fixture 时不需要安装化学等领域依赖。进程入口按登记的包名、接口版本和内容哈希加载实现；内核通过接口调用，不通过 if domain == ... 分支判断科学含义。

领域包可以依赖独立数值库和提供多个计算后端；每个后端声明兼容协议、资源需求、结果格式和恢复方式。更换后端仍需通过同一版本与来源检查，不因 Python 接口相同就视为结果可互换。

Codex harness 是 rsi_lab 通过 AgentRuntimeAdapter 管理的执行组件，登记为 codex_runtime，不另增一个领域层。应用侧提示、上下文和策略与开源 Codex 内部的 agent loop、工具调度、重试、上下文压缩实现分别标识；诊断必须指出改动属于哪一组件。源码修复面向 RSI-Lab 自己构建并启动的 Codex fork；官方桌面应用及本次编辑文档的聊天进程不作为隐含的版本切换目标。开源 harness 与 CLI、SDK、app-server 的关系见 OpenAI 官方说明；本文后续 runtime 管理契约是 RSI-Lab 的目标设计。

A.3 task、调度工作和外部执行的区别

task 是用户交付给系统的科学计算任务。一个 task 可以包含多个阶段、多轮模型决策和许多计算，不等于一次 API 调用或一次候选评分。

  • TaskSpec：科学目标、输入、约束和授权的声明。
  • TaskRun：执行该 task 的一次持续运行，持有预算账本和检查点。
  • Work：内核下一步可调度动作，例如请求一页证据、解析一个文件或检查一个补丁。
  • Effect：某项 Work 引起的实际外部调用，具有输入哈希、幂等键、资源预约和结果责任。
  • Artifact：原始或派生产物，持有创建它的版本与依赖关系。

task 不要求所有领域都采用“生成候选—评分”的形态。内核调度带类型的计算步骤；候选生成、身份查重、评分与批次只是化合物等领域可以启用的执行模式。相应 schema 和 Worker 循环通过能力契约接入，不能成为其他领域必须伪造的数据结构。

ScientificQuestion 表达 task 内的科研问题；ScientificInvestigation 组织实验、分析、检索或推导，并关联 Step/Work/Effect。二者不替代 TaskSpec、调度 Work 或 Meta Issue；科研解释更新不自动变成系统修复，关闭问题不改变 task 的冻结完成条件。

A.4 通用接口与能力注册

接口定义留在 rsi_lab.contracts。领域包返回类型化计划和结果；内核执行副作用、管理状态和计费。

接口 输入与输出 边界
validate_task(spec) TaskSpec → ValidationReport 检查领域输入、协议完整性和能力兼容性；不得擅填关键科学参数
describe_capabilities() → CapabilityManifest[] 声明 schema、版本、资源、允许变更范围、恢复处理器和结果有效性规则
plan_step(context, request) → StepPlan 只提出步骤、依赖与预期产物；不能直接执行工具
canonicalize(entity) → identity, normalized_ref, identity_version 在适用领域定义科学对象身份；身份版本变化必须显式迁移
execute(effect_input) → RawResultRef / KnownFailure / Unknown 只能由内核执行器在持久意图与预约之后调用
parse(raw_ref, parser_version) → DerivedArtifact[] 从保存的原始输出产生新派生版本，不覆写原输出
analyze(input_refs, analysis_spec) → DerivedArtifact[] 分析能力同样登记依赖、成本与工具调用，不能隐藏外部效果
assess_validity(artifact, protocol) → valid / invalid / unresolved + evidence_refs 判定科学数据是否适用于协议；未知和失败不可伪装成有效值
check_completion(artifacts, frozen_requirements) → satisfied / unsatisfied / unresolved + evidence_refs 按冻结任务条件判定完成；内核核对使用的要求与来源版本
assess_impact(change, dependency_graph) → invalidation_plan, reusable_refs, unresolved_refs 提议影响范围，由内核验证依赖闭包和兼容性声明
assess_comparability(evidence_refs, scientific_scope) → comparable / non_comparable / unknown + reasons, rule_version 领域包解释条件、单位、对象与方法是否可比较；未知不按兼容处理，模型辅助检查仍通过 Work/Effect 计费

CapabilityManifest 至少包含：capability_id, package_version, implementation_hash, interface_version, input_schema, output_schema, protocol_compatibility, resource_contract, effect_kind, idempotency_support, recovery_handler, validation_contract。

纯代码解析和外部计算使用不同资源契约。适配器内部需要新外部调用时，必须返回新的执行计划交由内核预约；不得在解析回放或状态重建中偷偷调用服务。新增分析适配器验收成功后即可注册供后续 Work 使用，不要求重跑整轮 task。

A.5 任务规格与冻结要求

TaskSpec 最少登记以下内容。此表是实现契约，具体阈值从任务授权与科学协议读取，不由本文生成默认值。

字段 内容
task_id, task_version, goal 任务身份、版本和科学目标
domain_id, domain_version, capability_bindings 领域包及选用能力的确切版本
input_manifest, protocol_ref, protocol_hash 输入身份、内容哈希和科学协议
frozen_requirements_ref/hash 阈值、数量、有效性、去重与其他不可由 Meta 修改的要求
step_dependencies, expected_artifacts 计算依赖及交付产物
budget, recovery_reserve 总预算、资源口径及修复恢复预留
meta_authorization_ref/hash 可改模块、能力、参数、科学输入及变更预算
completion_contract, stop_policy 完成判据、停止条件、在途执行处理方式
runtime_bindings rsi_kernel_artifact_hash、按 Lab/Meta 角色登记的 codex_runtime_binding_hash、模型路由、上下文策略与工具版本
memory_contract_ref/hash, memory_policy_ref/hash, source_access_ref 科研对象 schema、初始读取/提议/维护策略与预算、允许来源及保留/迁移条件；来源权限和冻结科学要求不能由记忆提议扩大

TaskSpec 与启动 RunConfig 是不可变起点，表中的精确版本是初始绑定。运行中发布通过追加式 ReleaseManifest / ActiveRunBinding 更新当前版本，至少记录 run_id, branch_id, parent_release_hash, task_spec_hash, frozen_requirements_hash, actual_protocol_hash, capability_bindings, rsi_kernel_artifact_hash, agent_runtime_bindings_by_role, memory_binding_hash, activation_seq。每个角色的 runtime 绑定指向 §11.6 的完整不可变清单，明确 Codex binary/config、适配器与会话契约；旧 runtime_artifact_hash 经显式 schema 迁移保留其原义，不用于同时指代 RSI 内核和 Codex。修复不覆盖启动配置、不改变 task_spec_hash 或冻结要求；派发读取本运行的活动绑定，结果保存实际版本。新协议或新 Codex 产物登记本身不切换任何运行；只有明确作用于该 run/branch/role 的发布才生效，其他运行和角色保持自己的绑定。

例如，当任务要求“至少 100 个达标 compound”时，数量下限 100、达标阈值、身份去重规则和所需科学证据均属于冻结要求。内核保存要求哈希；领域包负责解释 compound 和达标的科学含义。完成报告必须提供可追溯、去重后的合格名单及所用协议，不能把 100 次调用、100 条派生记录或同一化合物的多个构象算成 100 个合格 compound。

少量样本可以证明解析器、适配器或上下文改动可用，但不能替代最终任务的数量要求。局部验收通过与整个 task 完成使用不同结果字段。

task 启动后，Meta 不能通过修改配置、提示词、判定代码或新建协议版本间接降低上述要求。科学输入可在已授权范围内改变，但协议版本必须继续引用同一冻结要求；需要改变科学目标或冻结要求时，由用户提供新的明确任务定义，不能冒充原任务已经完成。

MemoryRuntimeBinding 是内容寻址清单，包含实际 memory_contract_ref/hash, memory_policy_ref/hash, selector_ref/hash, projection_ref/hash, compatible_schema_versions, migration_ref/hash?。初始值来自 TaskSpec；后续变更通过 ReleaseManifest/ActiveRunBinding 在安全点 CAS 切换，不能覆写初始配置或扩大来源权限。每个 packet/Effect 和科研提议保存实际 memory_binding_hash 与读取快照，按实际版本解释和恢复；在途调用保留原绑定。

A.6 版本、来源与选择性重算

每项产物至少记录：artifact_id/hash, artifact_kind, task_id/version, run_id, protocol_version/hash, capability_id/version, implementation_hash, input_refs/hashes, source_effect_id?, created_seq, supersedes_ref?, validity_status。生成决策还记录实际使用的模型路由、上下文策略、能力版本及 codex_runtime_binding_hash / runtime_generation；其下游 Effect 关联来源决策。原始输出与解析结果拥有不同身份。

复用不是只比较文件是否存在。每个计算步骤的复用键由它实际依赖的输入哈希、科学协议的相关字段、实现语义版本、工具/模型配置及随机种子等组成。协议整体版本变化会留下新的来源关系，但不要求所有未受影响的步骤失效；跨版本复用必须有可验证的字段依赖与兼容性依据。

变化 保留 追加或重算
结果解析 bug 已保存原始输出、原调用成本和原始来源 新解析结果及依赖错误字段的统计、判断、报告
新增分析能力 既有计算与有效产物 小量已有数据上的验收产物，随后需要该分析的步骤
上下文组织调整 原页面、已认证回执、已完成计算 新工作视图与后续调用；复核缺失必要信息造成的具体判断
Codex harness 源码修复 已完成调用的原始输出、费用和真实运行版本 新 binary/config/adapter 绑定、后续调用及受影响判断；只沿依赖闭包复核，不默认重跑任务
已授权科学输入改变 与变更无依赖且仍兼容的产物 新协议版本、受影响计算及其依赖闭包

Meta 先提交 invalidation_plan，列出改变的语义、直接依赖、下游失效集合、可复用证据和恢复点。内核校验后追加失效事件，将旧派生结果标为当前用途不可用；旧记录保留。重算完成前，受影响工作等待，其他不依赖这些结果的工作继续。

依赖信息不足时将相关产物标为 unresolved 并调查，不能默许复用；也不能以不确定为由默认启动整轮对照。确实全量受影响时才重算全部受影响节点，并记录原因。重算用于恢复结果正确性，不自动构成一项独立收益比较实验。

恢复代码版本不会删除新版本已经产生的事实。若已发布版本随后失败，回退到已知可用实现，并识别该版本生成或影响的派生产物，追加失效/复核任务；原始输出、调用成本和运行轨迹继续保留。

来源或协议变化也影响科研解释：相关 Claim、Method、研究计划及摘要进入待复核，按精确版本依赖检查。需要复核不等于必须重算全部原始数据；重解析、科学判断修订与外部重算分别计划和计费。旧判断和历史决定保留当时实际可见版本。

科研状态额外保留实际 memory_binding_hash, read_snapshot_seq, proposal_source_effect_id。重建摘要、检查或判断时使用登记的 schema/选择/投影版本；缺少兼容实现时报告 blocked/unsupported，不能默认改用最新机制重解释旧记录。

A.7 Meta 可修改的所有权边界

授权由 task 绑定，能力由注册表声明，二者交集决定 Meta 的实际可写范围。授权检查在内核执行，不能仅靠模型自述。

对象 默认处理

已授权的内核可修复模块 走相同路径，另外验证持久化、幂等、恢复与接口不变量；在安全边界切换实现

科学输入与协议 在授权范围内追加协议版本和影响计划；保持冻结要求

常规授权内操作无需逐次请示。只有缺少决定继续任务所必需的用户信息或授权时才提问；等待这一信息期间继续处理不依赖它的工作。预算不足、验收失败和技术错误先按已登记的停止、恢复或重规划规则处理，不把每次失败变成用户审批。

A.8 三层解耦的验收

  1. 内核不安装任何具体科学依赖也能运行契约 fixture；静态依赖检查不出现对具体 rsi_domains 实现的导入。
  2. 同一内核通过注册表运行至少两个不同能力集合；更换 task 的科学输入与完成要求不修改内核代码。
  3. compound 阈值和至少 100 个达标结果的要求仅从该 task 的冻结配置取得，领域包实现解释，内核验证版本与执行边界。
  4. 修改解析器可以重用原始输出，新增适配器可以处理已有数据；都能指出本次实际计算与复用的产物。
  5. 科学输入改变后，可证明无关计算被复用、受影响结果被重算，旧协议的结果不能被无来源地冒充新协议结果。
  6. 模块越界修改、预算扩张与冻结要求改变均被执行器拒绝；合法补丁能在局部验收后接入当前 task 的后续执行。
  7. 同一 AgentRuntimeAdapter 可以按登记绑定运行原版和修复后的 Codex；构建、实际启动版本、当前任务续跑和失败回退都有独立证据，不因只生成 diff 就声称执行层修复完成。

这些是目标架构的验收条件，不能从目录存在、接口声明完成或历史实验通过推断已经满足。

确定性指相同已提交事件、配置和版本产生相同控制状态；模型和外部计算本身不要求确定。事件回放只消费归档，不重新调用外部服务。

  1. I1 原始事实不可变。 调用输入、原始输出、评价、页面和回执只追加；修订结果引用旧版本，不覆盖历史。
  2. I2 冻结要求不可自改。 Meta 不能更改任务目标、阈值、达标定义、已冻结的数量要求（如本化合物任务的至少 100 个达标 compound）、预算上限或自己的授权边界。
  3. I3 调度不伪造证据。 到期、容量变化和租约释放只推进调度版本。
  4. I4 等待不占派发槽。 parked 事项和 pending 请求不占执行租约；未知外部效果仍持有未决责任。
  5. I5 执行先有持久意图。 所有外部调用都绑定已提交 effect、版本、输入哈希、预算预约和幂等键。
  6. I6 未知不等于失败。 无法确认未执行的动作不自动重发，也不释放相关身份和费用预约。
  7. I7 交付按实际内容认证。 摘要、指针、存根和请求成功不代替原页 ACK 或原生记录回执。
  8. I8 版本和影响可追踪。 每个结果绑定实际代码、领域包、协议、输入和解析器版本；只重算受影响依赖。
  9. I9 发布与回退有责任人。 发布必须有验收证据；恢复、未决效果和迁移义务不能因释放名额而丢失。
  10. I10 预算守恒。 实际消费与未决预约不超过授权上限；失败、修补、验收和恢复都计费。
  11. I11 修复完成需要续跑。 通过测试、写入配置和实际解决问题分别记录；续跑以真实后续事件证明。
  12. I12 工程结论与收益结论分开。 验收通过不自动建立任务分数、科学发现或总体效率的因果提升。

ScientificInvestigation 问题/判断版本、方法、输入、可选检验承诺、Step/Work/Effect 与产物绑定 执行、结果判定、解释状态分开；不是 Meta investigation 或可选 ResearchExperiment
MethodExperienceRevision 真实尝试、方法、环境、失败/恢复、反例、验证范围 可复用解释保留条件；可执行方法变更仍走 ChangeEngine
ScientificDecision 调用、实际读取快照、相关判断、选择及理由、未知、后续行动 保留当时依据；显式引用不证明因果收益
SourceTombstone，可选 source_ref/version、允许保留的 hash/provenance、授权/原因、删除处理器与状态 pending_delete / deleted；仅在许可的来源删除能力启用时使用，读取 unavailable 与存储损坏分开

Work.kind 为封闭注册表：lab_step, candidate_evaluate, meta_worker_decision, inspector_discovery, disposition, evidence_retrieve, effect_reconcile, patch_build, validation_step, reparse, recompute, release, rollback, resume, change_settle, change_explain, memory_match, memory_review, memory_consolidate。可选研究另注册 replication_step；获准开启来源删除能力时另注册 source_retire，绑定受信保留政策处理器。新 kind 必须同时提供权限检查、资源单位、执行器、恢复处理器和终态；本地协调 Work 不持有包住子调用的外部租约。

Codex 修改复用这些 Work kind：patch_build 产生源码和二进制，validation_step 产生真实检查回执，release / rollback / resume 由 RuntimeSupervisor 执行已登记处理器。命令行构建、探测和进程操作也保存 Effect 与资源预约；本地进程句柄不可查询时按 unknown 处理，不把重启本身当作再次执行许可。

问题键由 component, mechanism_type, intervention_target, applicability, key_schema_version 规范生成。重复同一事件幂等返回；重复同一事实只增加 seen_count，不增加证据版本。新反证、条件变化或显式重审才生成新的调查工作。有效但暂无资源的提案保留 queued，不能当作已否决。

4. 工作集、依赖与安全点

Issue 描述问题；Work 描述下一动作；Wait 描述依赖。open/queued/parked 持久条目不设执行名额上限。默认 8 条仅指可淘汰的工作摘要缓存，不参与正确性准入。真实存储容量耗尽应报告资源问题，不能丢弃已有义务。

资源分别计量：外部任务执行许可默认 1、只读恢复探测许可默认 1、候选/计算身份预约、变更发布锁。初版同一运行最多一个候选版本进入发布/试用阶段；多项调查和候选准备可排队，锁不阻止无冲突的 Lab 工作。后续可扩展按组件作用域加锁。

安全点有三类：正常步骤/批次边界；失败或容量阻塞后且外部效果已确定的恢复边界；经检查点确认的受控进程重启边界。不能要求一个已卡住的批次先正常结束，才允许 Meta 修复它。必要时暂停受影响 Work，保存成功前缀和 resume point；独立工作继续。

安全点只能切换未开始工作的版本。已派发 Effect 保留真实输入版本，迟到结果按其实际版本归档。需要中止未完成 Batch 时登记 aborted/superseded，保留已完成评价和成本，恢复只从未执行或明确需重算的部分开始。

close_issue(resolved) 要求问题的验收与续跑证据齐全。失败/未决效果、回退、未结算评价或迁移义务仍存在时保持 open；可取消请求显式取消，已产生的页面和回执不删除。无可行修复可以有理由关闭为 closed_unresolved，不能伪称已解决。

科研待解释结果、待复核判断与未完成计划作为持久工作集映射到已注册 Work/Wait；不设新的“记忆槽位”准入上限。必要失效通知与当前任务义务优先，可选归纳在共同资源内接受有界服务。队列超出上下文时返回数量与继续入口，不丢弃未处理对象；维护记录本身不创造科学进度。

5.2 三类额度

  • 任务执行额度：Lab 的模型、工具和科学计算。
  • 修复与验收额度：调查、编码、重解析、小样本及必要后续验收。启动时预留，避免 Lab 卡住后只能等新的批次产生 credit。
  • 恢复预留：已承诺的对账、取消和恢复。恢复/结算的纯代码操作不需要模型 credit，始终可以调度。

三者都是任务总预算内部的子账户，不能重复算作新增额度。Meta 的常规巡检、修复解释和系统策略探索使用 Meta credit；Lab 科研解释与 memory_review 使用任务执行子预算，不要求 Inspector token 或 Meta discovery credit，仍受共同真实资源限额约束。已确认阻塞的必要机制修复用 repair_allowance，不因发现令牌耗尽而饿死。repair_allowance 还预留疑似阻塞初诊：每个停滞 epoch 最多 1 个 episode，每个 run 最多 3 个 episode，每个 episode 最多 3 次模型调用，允许“提出取证 → 获得材料 → 判别”的闭环在未确诊时执行。该预留包含在 repair_allowance 内，须登记 token、时间和工具上限，不是额外预算；取证后的续调和格式重试共用 episode 上限，无需新的进度/token/可选 credit。不能要求先有进度才能发现为何没有进度。每个 Issue 的调查和修复尝试总量有上限，重开或 wait 不能清零。

准入预约最大费用，实际用量结算差额；unknown 保留最坏情况预约。支持父子转拨：outstanding(node)=unallocated(node)+sum(outstanding(children))，根账户满足 limit=free+consumed_once+outstanding。父 delegated 是关系字段，不再占一次额度；released 仅为审计字段。limit-consumed 与可新派发的 limit-consumed-outstanding 分开报告。

时间使用登记 deadline，不能以调用数近似。模型调用上限可为空，但真实 token、时间和计算额度必须明确。新变更在准入时同时预约验收、必要续跑检查和恢复资源；修复局部预算耗尽则停止该修复、结清效果并撤销候选，释放后任务可用剩余合法预算继续。回滚后仍有原故障时只暂停该依赖，不谎称可以安全继续。

科学记忆检索、解释复核与归纳从任务执行额度中的登记子预算支付；Meta 对记忆机制的修复使用相应修复额度，已承诺对账遵循恢复预留。所有模型、工具、索引与摘要工作分别记录实际资源，既有调用内处理的解释不重复收费。记忆写入数、摘要数和维护事件不能增加 credit 或重置尝试次数。

6. 外部效果与崩溃恢复

TX1 准备事务： 重查 Work、权限、版本、必需依赖与预算；以固定读取快照和实际 runtime/memory binding 构造完整 packet/input blob 及候选交付清单并持久化；提交 Effect(prepared)、Work(leased)、预约和 outbox。此时仅物化内容，不授予实际读取权限或 ACK；提交失败绝不调用外部服务。

TX2 领取事务： 在同一短事务内重查 Work、§13 的用途/停止准入规则、权限、当前必需依赖及失效水位、该 Work 实际依赖的活动 runtime/memory 绑定和有效预约；模型调用另查 generation，再 CAS prepared→dispatching 并登记本次准入版本。finalizing 禁止新科研推理，但已登记的必要对账/取消/回退/恢复可按恢复权限与预留准入，不得借此启动新科研工作。检查失败保留原 packet 与来源，取消尚未派发意图并释放确定未消耗的预约，后继 Work 按新快照重建；不能原地替换原 packet。已 dispatching/unknown 的 Effect 不走此取消路径。TX2 提交是派发许可的线性化边界，随后退出事务才执行外部 IO；并发更正若在此之后发生，保留实际调用及费用，在结果提交时重新处理适用性，不盲目重发。

TX3 结果事务： 先持久化原始结果/错误，再核对 Effect、provider handle、实际绑定、传输/完成回执和 packet hash；根据受信证据登记实际交付、原生读取权限及页面 ACK。原子登记结果、合法提议或逐项拒绝、后继工作/待处理水位和预约结算；支持检查及记忆提议在提交时再次核对精确依赖版本。调用期间来源已更正的解释可按历史快照保留，但由控制器标记 needs_review，不能作为当前已检查依据；相关后继动作受阻并排入新版本复核。非法/过期解释不丢弃真实结果、已认证交付和费用，也不让一次成功计算重新变成未执行。数据库事务失败从已落盘回执幂等重放。

网络超时、断连和进程丢失默认 unknown。只有已知未执行或明确失败才为 failed_definite。若外部服务无查询/幂等能力，明确报告未决，不宣称自动 exactly-once。

普通 Meta Worker 使用登记 priority_band（0–2）和 (ready_seq, work_id) 稳定排序。连续可负担且被跳过 8 次普通准入机会的 Work 进入 aging FIFO；依赖不满足不算饥饿，seen_count 不影响优先级。有限服务延迟只在资源可用、外部能结束且负载可服务时成立。

常规 Inspector 发现需要 token 与可选 credit，积压达到 8 暂停、降至 4 恢复。积压按去重的有效 Proposal 和 ready Meta Worker Work 计，parked 不混入。暂停发现不阻断证据入账、覆盖 backlog、已有请求、恢复、修复或结算，也不阻断独立计额的疑似阻塞初诊。预算或反压导致的未巡检记录为 deferred，不能输出 no_action 或标为已经检查。

fastlane 仅由确定性规则产生 ChangeProposal，省掉一次提议调用；按 (rule_id, input_revision, baseline_hash) 去重，仍走同一权限、验收、发布、恢复和续跑路径。失败或不确定变更不因下一 tick 自动重试；需新证据、候选版本或有界显式重审。

科研记忆 Work 的派发归属：memory_match 仅做有界本地索引匹配，计入 code_work_per_tick，并持久化待处理水位；不能把全量匹配/语义推断标为无限优先的 critical local backlog。需要模型解释的部分登记 memory_review，由 Lab 或 task 指定的科研处理器执行，使用任务执行额度。必需复核作为受影响 Lab 步骤的前置依赖，只阻塞该 blocking_scope；无关 Lab 工作继续。普通复核进入 Lab 通道并按 ready_seq/work_id 与登记的 aging 规则服务，不消耗 Meta discovery credit。独立 memory_consolidate 是可选低优先维护，只在有可分配额度且不挤占必要义务时准入，可记 maintenance_deferred；不得为保证写入量阻塞任务结束。

§7 派发顺序中的“Lab”包含上述科学解释与复核；用于修复机制本身的诊断仍属 Meta，按原修复优先级执行。证据到达、读回执和维护结束本身不产生新科学进度。前置复核不能等待被自己阻塞的后继步骤才触发：准入依赖必须指向已有来源或独立生产者，发现等待环按 §8 处置。

7.1 主动发现的责任与唤醒

Meta 对发现问题负责。 Lab 不上报、工具不报错、已有检测规则不命中，都不能免除巡检。Inspector 根据冻结目标、当前计划、实际行为和原始产物判断系统是否在做正确且有用的工作；可以提出规则未覆盖的新假设。确定性规则负责提醒和强制不变量，不能定义模型允许发现的全部问题。

巡检范围包含登记的 Codex harness 及其适配器。事件协议异常、工具调用/重试偏离、压缩后的证据丢失、会话恢复失败或无告警的行为异常都可触发调查；确认执行层根因后自动进入 §11.6。已预授权的源码修改、编译、验收、切换和回退连续执行，不等待用户再次逐步指令。

事件提前检查 错误、证据矛盾、来源修订、异常重复/消耗、容量拒绝、预期结果缺失 按来源版本合并唤醒；已有关联 Issue 时直接更新该调查
疑似停滞初诊 没有预期进展的具体 Step、生产者、依赖与可恢复动作 watchdog 登记一次 stall epoch；使用预留初诊额度，不等待新进度或问题预先确诊
变更后跟进 修复是否实际生效、相关后续结果是否正常、是否产生回归 走已有 Continuation 和已预约验收；不再重复收费创建等价巡检

watchdog 使用注册工作流的预期里程碑、结果 deadline 和相关状态；默认在应有进展但持续 300 秒无相关进展时生成疑点。已声明时长内正常运行的计算、等待尚未到期的外部依赖不因“没有新批次”自动判为故障。没有新证据、没有逾期预期、没有必要跟进时，定时 tick 只推进本地检查，不调用模型。

stall_epoch 绑定 run、受阻对象、预期里程碑和相关状态签名，定时器、重复回调和 Meta 自己的日志不能刷新它。一次初诊 episode 后必须登记转入已确认问题的修复、具体依赖等待、关闭疑点或初诊额度不足；同状态不按下一次时钟重复诊断。额度耗尽但未确诊时保持 deferred/具体等待，不能自动升级为无限必要修复。只有相关执行/依赖状态实质变化并形成新的逾期条件才产生新 epoch，整个 run 的初诊次数也不重置；同 episode 的取证返回继续原调查，不另开 episode。

7.3 主动取证与持续调查

发现与修改使用不同门槛。可疑但尚未确诊的现象即可建立 provisional Issue，由 Meta Worker 接手；只有证据、影响、授权和可验证方案足够时才进入 Change。根因未明时问题键使用可核对的症状与作用域，后续根因细化保留同一 Issue 或显式合并关系，不以改名重置历史和额度。

Inspector 和 Meta Worker 均可主动请求授权范围内的事件原文、调用输入输出、raw/派生结果对照、相关代码与配置版本、检索遗漏记录和依赖信息。初次调查默认最多 3 个有界取证请求，并受实际调用/token/字节/时间预算约束；不足时须在同一 Issue 内提出具体后续计划和剩余额度，由控制面准入，不重建问题来获取新额度。已获得材料尽量复用，但实际交付认证仍按 §9 处理。

Meta Worker 接手时独立核对 Inspector 的依据，保存：

Investigation
  issue_id, scope, source_versions, meta_worker_work_id
  observed_facts[], hypotheses[], alternative_explanations[], counterevidence[]
  evidence_received_refs[], evidence_delivered_refs[], missing_evidence[]
  impact_if_true, next_action, discriminating_check, stop_condition
  related_work/result/component_refs[], wake_condition
  remaining_attempts, budget_account, incurred_cost

调查按“最能区分解释且成本最低的下一步”推进：先读原始记录，再对照实现/协议，再运行授权内的最小复现或检查。已有 raw 可解决的问题不重新调用科学计算。每一步明确预期观察与什么结果会推翻当前解释；单次直接实现证据可以足以定位 bug，不必机械等待重复报错。

合法取证、局部复现与修复不逐次询问用户。缺材料时优先自行查找；只有必要用户信息或授权确实无法取得才提问。unavailable / truncated / not_delivered 保持不同原因，不能变成“证据支持无问题”。影响冻结正确性的未决依赖继续阻塞；其他合法工作继续。

Issue 订阅相关 Work、结果、协议/组件版本和验收/续跑事件。新材料到达自动恢复同一 Meta Worker 的下一步；停放必须带具体依赖和唤醒条件。相同范围已有可执行调查时优先继续它，巡检附加新证据，避免不断开新问题而不完成旧调查。该优先级仍受 §7 的 Lab 公平性和总额度限制。

Inspector / Meta Worker 发现失效引用、解释遗漏或内容性疑点时，可用 request_scientific_review 关联目标科研版本、实际交付来源、发现与局限。控制器按目标/来源版本和用途去重为 Lab 的 memory_review；接收调用重新交付所需来源，不能继承 Meta 的引用权限。纯内容复核无需先建代码 Change，也不授予 Meta 覆写 Claim 的权限；同一发现若同时表明检索/运行机制故障，可另建关联 Issue/Change。复核完成返回来源绑定结果，机制 Issue 仍按其验收与续跑契约结算。

7.4 覆盖证明与有条件的 no_action

巡检输出必须逐项覆盖本轮登记的检查项，包含明确的负面判断。控制面检查漏项、重复项、未知项、来源版本和交付权限；格式完整只能证明报告完整，不能证明模型判断正确。

InspectionResult
  inspection_id, trigger_refs[], plan_hash, source_cutoff_seq
  check_assessments[{check_id, scope, outcome, evidence_refs[], reason,
                     limitations[], next_action?}]
  additional_findings[], issue_links[], evidence_requests[], scientific_review_requests[]
  checked_source_refs[], uninspected_refs_or_cursor, next_inspection_condition

outcome = suspected_problem | no_issue_found | insufficient_evidence | not_applicable

no_issue_found 只对已读来源与本次范围成立；not_applicable 必须说明适用性理由。未完成检查或关键证据不可得时必须是 insufficient_evidence，并安排取证、等待或留下明确未决。no_action 仅允许在本轮检查项均有依据地无问题/不适用、没有可行动新发现时输出，并带覆盖范围、抽样限制和下次条件；它不宣称全系统健康。

分开记录事件消费游标、实际交付范围和完成检查的来源版本。扫描过索引不等于模型看过原文，交付过也不等于完成审阅；仅由已归档且通过结构校验的巡检结果更新完成覆盖。完成覆盖只更新实际交付且已作出 suspected_problem 或 no_issue_found 判断的来源范围；not_applicable 只完成该检查项的适用性判定，insufficient_evidence 及未交付来源继续保留为未完成覆盖。截断、容量不足、反压和预算不足的材料留在持久 backlog；增量摘要或缓存淘汰不推进其已检查状态。

同一输入版本的模型失败/非法结果最多按配置重试一次，每次计费；耗尽后巡检保留 deferred 及未覆盖项，不伪造 no_action。仅新相关来源/能力版本、容量改变或登记的有界显式重审可重新安排；重启和重复通知不重置次数。日常巡检输出、ACK、预算结算等自身事件不算新的科学事实，避免巡检观察自己而无限自激。

7.5 主动性如何验收

验收分两层：脚本化 Meta 和故障注入证明无报告唤醒、去重、取证、连续调查及预算路径可达；真实模型在预先留出的有标签案例与正常案例上评测是否能发现并解释问题。不得只给模型标好的 issue 描述后把成功修复算作自主检测，也不能用 scripted 输出证明模型识别能力。

报告无 Lab 报告的发现数、首次可见线索至发现/调查的延迟、各组件/版本的已检查和未检查范围、真实问题检出/遗漏、正常案例误报、调查完成率、重复调查率和每个已验证问题的总成本。检出率/误报率需要独立参考标签和明确分母；未知真值的在线运行只报告可核对的过程指标。

未报告问题不自动等于漏检，产生更多问题也不自动等于更主动。成功标准是系统在用户介入前发现可行动疑点、主动取得判别证据、在预算内处理到明确结果，并使任务得到实际推进；合法的无问题判断与被反证关闭的假设同样保留。

8. 等待与容量处置

Wait 必须绑定具体 dependency_id、已见版本和可查询的生产者。注册类型包括 request_outcome_changed, capacity_signature_changed, issue_evidence_changed, change_outcome_available, continuation_available, protocol_revision_available, scientific_evidence_changed, scientific_result_available, memory_review_due, timer_due；可选研究另提供 replication_finished。已失败/取消生产者立即产生相应处理，不注册永远等成功的 Wait；依赖闭环触发一次处置。

默认 deadline 为 8 个进度单位或 300 秒先到者；到期先落持久事件。唯一键 (wait_id, wait_epoch, disposition) 保证即时容量阻塞和后续 deadline 共用一次处置。处置准入原子消费 allowance，模型失败也不能重置已尝试事实。相关依赖/容量版本真正变化才能建新 epoch，纯时间和计数增长不能重置。

容量不足时 Request 保持 blocked_capacity，保存 need/have、packet 版本、容量签名和原 page_token；另建只含身份、容量、义务与允许动作的最小处置 Work。存根不产生 ACK、不推进 cursor、不授权引用。已物化页面如需收窄，supersede 原请求后建新请求，原页与回执保留。

容量签名包括内容、必需依赖、策略、投影及可用 byte/token，不含无关的全局序号或时间戳。每签名最多自动重规划一次。模型处置包本身也放不下时直接报 packet_unrepresentable；不要继续发超限调用。预算不足保留具体未决对象与可恢复动作，不将 parked 写成已解决。

每个 Wait / disposition 继承 owner_refs, purpose, actor_binding, budget_account, blocking_scope。Meta 问题按原 close_issue 等命令处置；科研等待仅允许收窄/重规划请求或搁置相关 Work，由 Lab/登记科研处理器处理，最小诊断包不能关闭 ScientificQuestion 或产生支持结论。科学处置 allowance 来自任务执行预算，不要求 Meta token；同 Wait epoch 仍最多一次。计时 deadline 处理等待，没有科学进度时也可到期，不以归纳/复核次数伪造时钟。

9. 上下文、证据与 ACK

最终 UTF-8 序列化字节与登记 tokenizer 的 token 数都须通过，并预留输出空间。规划与派发使用同一纯构造函数 build_packet，返回 packet/hash 与候选 delivery manifest，完整 hash 和实际 memory/runtime binding 进入 Effect；禁止检查后追加内容。预览、选中或物化不证明实际交付。实际交付权限与 ACK 仅由 §6 TX3/受信交付对账根据真实回执登记，不能由构造函数或模型自报产生。

调用模式 初版工程默认 必须保留

每页绑定 request_id, page_token, from/to_cursor, content_hash, scope, dependency_manifest。ACK 按 (request_id, page_token) 唯一，并关联已完成调用、实际 packet hash 与受信交付回执；重读可有多次呈现但 cursor 只推进一次。模型输出格式无效不抹去已认证交付，命令拒绝另记；只有派发意图、服务端接收或未知完成状态时，不推断完整交付。页面 ACK 和原生引用分别认证；部分交付不能写成全请求 delivered。原生权限限定到 call、版本和 locator；用于校验提议的 actual_read_manifest 由控制器查询受信记录，不能接受模型提供的清单作为权威。

Inspector→Meta Worker 交接重新算容量，原未确认页保持不变；不因消费者改变删回执，也不自动授权另一调用引用。记忆判断追加支持/反证、适用协议和来源；依赖修订后标记 needs_review，不能继续静默引用失效结论。

Scientific Memory 的检索结果是 build_packet 的输入，最终只物化一个完整 packet，实际派发后按受信回执认证，不在检查后追加另一份记忆。观察卡的内容、条件和精确引用来自同一原生证据：完整 record 与字段投影使用不同 locator，投影另存规则版本与 source manifest；实际交付哪部分只认证哪部分。工作上下文优先恢复未结工作、相关对照/反证和失效提示，选择策略及省略原因一并留档。

Agent 局部上下文与共享数据的边界。角色、会话、数据作者与访问范围是不同维度。Lab / Meta 是职责角色；同一角色可以有多次调用或多个实例。记录由某个 agent 产生，不等于只供该 agent 使用；位于共享数据库，也不等于自动进入所有 agent 的上下文。

10. Lab 执行和领域批次

10.1 通用步骤契约

Lab 选择已注册能力，控制面检查输入、权限、依赖、版本和预算，再创建 Effect。完成原始计算、解析、分析和科学判断分别建结果节点，避免一个解析器错误让整个计算回滚重跑。task 的完成条件由领域 validator 在当前有效结果上检查；模型报告“完成”只是提议。

相关步骤携带 ScientificQuestion / ScientificInvestigation 引用，按真实输入身份绑定回执和产物。执行完成后登记待解释结果，下一次相关 Lab 调用可修订判断或说明证据不足；执行完成、解释完成和 task 达标分开。仅声明为前瞻检验的步骤需要事前冻结预测与比较规则。

10.2 化合物工作流示例

以下属于 rsi_domains 的筛选工作流，不写死在 rsi_lab 中。默认每批最多 8 项、最多 2 次生成尝试、一次缺口修补；修补拒绝比例默认 0.5，合法范围 [0,1]。这些工程参数与冻结科学阈值分别存放。repair 在对应适配器验收通过后可在当前任务安全点开启，无需配对实验。

  1. begin_batch 冻结历史、策略、协议和预算；target_count 取配置与可分配评价额度的小者，评价预约从父账户转拨。
  2. attempt 0 保存完整原始输出、解析版本和候选来源；预检结构、规范身份、全历史/同批重复及他方未决预约，不做评价。
  3. 合法新候选保留。首轮空/格式错误或缺口且拒绝比例达登记条件时，attempt 1 仅补缺口；多余候选记 surplus，不扩批或追加第三次。
  4. 派发前按最新历史、协议兼容性和身份预约复检，逐项执行评价并提交，保留成功前缀。
  5. 已准入效果均确定后只提交一次 batch_committed；unknown 则 blocked_unknown，不重复评价已成功项、不虚增进度。

Batch、Attempt、Call/Effect、Evaluation 是四种身份；修补调用照常计费，但不增加批次、Meta credit 或巡查时钟。连续三批零产出触发一次停滞处置；无合法修复/新策略则 stalled，不无限生成。

候选身份使用领域 canonicalizer，命中哈希后核对规范表示。计算查重键同时包含实际输入、评价语义/协议兼容性及计算能力版本：同 compound 的同一有效计算不重复；协议变化需要重新计算时不会被“历史见过该分子”错误禁止。至少 100 个达标 compound 按冻结身份和资格规则去重计数，重新解析或同分子多次评价不能增加独立 compound 数。

重复、无效、未接纳、已执行及 unknown 均保留逐项身份回执。已有结果的真实值、协议与证据引用反馈给后续合法生成步骤，不要求模型判断未呈现全历史的成员关系；独立重复或协议改变仍按冻结规则处理。新回执不扩充本批尝试次数或实际评价额度。

10.3 Scientific Memory：通用科研状态与记忆机制

Scientific Memory 以研究问题组织记忆，以证据约束判断，以新结果推动修订，支持实验、计算分析、观察、复现、文献综合与理论推导。它保存研究状态，并为下一步行动重建相关上下文。以下是目标契约。当前仓库中的运行账本与版本化事实不等于本节六类科研对象和完整记忆机制均已实现；功能及科研收益须分别验证。

10.3.1 三层职责与六类科研对象

rsi_lab.memory 负责对象版本、来源关系、依赖新鲜度、检索协调与待处理状态，复用 store、results、context 和 runtime。rsi_domains 提供对象身份、科学条件、可比性及结果解释规则；task 提供冻结目标、来源权限、协议和资源上限。Question 的细化或修订不能改变 TaskSpec 的冻结要求。

10.3.2 登记、关联与判断修订
  1. 登记实际材料。 适配器保存实际取得的内容与定位，区分全文、摘要、元数据、截断和不可访问。原始观察、模型预测、协议评价、文献陈述、推导与执行失败分别标识。外部材料是来源，不从其文本继承执行指令或权限。
  2. 关联问题与条件。 按对象、方法、问题和科学范围建立候选关系；领域检查返回 comparable / non_comparable / unknown 与原因。相似文本不自动建立支持或矛盾，同源转述不增加独立支持。
  3. 匹配新增证据。 新材料到达后，有界匹配开放问题与当前判断，提出 supports / challenges / context / derived_from 关系并排入复核。该入口独立于旧来源更正，避免尚无依赖边的新反证被遗漏。语义判断需要解释检查，匹配本身不能确认矛盾。
  4. 提交解释版本。 Lab 或已授权分析角色可提出新判断、修订或暂不判断。校验实际交付引用、预期版本和权限后，将新版本、替代关系、依赖与投影一致提交。重复相同提议幂等返回；过期写入不能覆盖较新解释。
  5. 传播来源变化。 来源更正、撤稿、解析修复或方法变更触发相关 Claim、ScientificInvestigation、Method 和摘要复核。沿版本依赖传播，并在读取/执行前检查新鲜度；批量传播未完或检查达到上限时返回 needs_review 与未完成范围。

支持与挑战关系绑定具体命题版本。新版本缩小适用范围时，旧反例仍保留，但可通过显式理由改变它与新命题的关系，不能机械继承标签或静默删除。分支合并保留不同解释，最后写入者不代表科学共识。

提交时复检与持久队列：来源/结果登记事务同时写入对应 dirty 水位或幂等 pending 标记；有界匹配推进 processed 水位与创建复核 Work 必须同事务提交。崩溃重放不得先推进游标再遗漏后继工作。新 Claim、支持检查或结果解释提交时，将读取的精确依赖与当前相关失效水位再次比较；仅检查目标 Claim 的 expected_version 不足以发现来源在调用期间变化。旧解释/检查绑定原快照保留，其当前投影为 needs_review；旧版本复核不能关闭新 dirty_revision 的义务，后继动作重新检查所需条件。提议失败单独留原因，不回滚已登记的执行事实或重复结算。

新证据/更正与真正的命题版本变化可触发有界匹配。支持检查登记、ACK、队列状态、归纳摘要与无变化 bookkeeping 不作为新的独立原始证据；其必要状态变化只唤醒已有依赖工作，不能自触发无限新复核或归纳。待检查、已检查与已替代等状态来自追加事件和投影，历史命题、证据关系及检查记录不原地改写。

10.3.4 按问题构建本次工作上下文

一次读取指定 question_ref, decision_context, scientific_scope, snapshot, role, budget；调用者不能用自行填写的 scope 扩大权限。选择顺序为：

  1. 恢复目标、约束、未结行动、新结果、提交回执和关键失效提示。
  2. 精确查询已有工作、对象、数据/方法版本和显式来源引用。
  3. 取回相关判断、可比较的参照、支持、反证、竞争解释与执行经验。
  4. 以剩余容量补充关键词、结构或语义召回；相关性只决定候选材料，不决定科学支持。
  5. 将判断与关键依赖/已知反证作为组交付。可选材料可省略并记录缺口；当前判断或行动的必需依赖未完整交付时，必须阻塞该判断/行动，补充分页或合法收窄任务后再执行，无关工作可继续。收窄不能删掉冻结要求或原行动所需的关键反证。

较旧、低分、失败或否定结果可以比近期高分记录更重要。精确查重使用完整授权索引与领域兼容性规则；已有结果的身份、条件和真实回执反馈给后续合法调用。指定的独立重复实验使用新行动身份并接受协议检查，不因曾见过相似对象而自动禁止。

观察卡由同一原生证据生成，显示对象、内容、条件与精确引用。实际交付整条 record 才能认证该 locator；字段投影使用单独版本化的 projection locator 和 source manifest，展示摘要不能授予全文引用。页面 ACK 与原生引用继续分别认证，遵循 §9。

所有内容进入 §9 同一次 build_packet 的字节和 token 总预算，不能将 memory 当作检查后的额外附件。记录最终序列化内容/hash、实际交付引用、选中/省略原因、查询与投影版本。语义检索不保证发现尚未关联的所有反证，需独立测量漏检；许可访问、实际交付、显式引用和因果使用分别报告。

10.3.5 研究行动、结果与下一次选择

ScientificInvestigation 支持普通探索计划，以及需要声明时启用的前瞻检验承诺。探索性分析可形成事后假设；前瞻检验须在新结果产生前冻结 claim_refs, inputs/controls, prediction, comparison_rule, exclusions, known_confounds 和内容 hash。已有结果可作为参照，不能重新计为前瞻预测。

同一响应提出的新判断与计划，先提交合法 Claim，再解析为精确版本，冻结计划后才准入执行。非法实验卡记录原因；本身合法的工作可按 task 预先登记的规则作为未归因探索接纳。普通探索不必编造假设或预测。

请求、对象/样本、输入版本和产物通过稳定身份绑定。过滤、去重、重排、并行完成及预算截断后，不按列表位置配对。执行状态、结果判定和解释状态分开：完成执行不代表完成解释；未知外部结果走 §6 对账，不盲目重试。

前瞻结果按冻结规则判定，并保留多指标、部分结果、同分/不确定及无法比较。定性材料保留判定规则与复核者；理论结果保留前提、证明义务和反例。下一次相关研究调用可保留判断、缩小范围、修改解释或暂不判断，结果与 ScientificDecision 关联；最后一批没有后续解释时明确 awaiting_review。

未结工作包括待解释结果、待复核判断、未完成计划与信息需求。运行时将其映射到已登记 Work/Wait，按当前决策影响、依赖失效和等待时间分配服务；显示剩余数量。等待有具体生产者、唤醒条件和 §8 deadline，不能因存在唤醒条件永久绕过检查。搁置保留原因和恢复入口，不删除未决义务。

10.3.6 长期归纳、遗忘与跨任务迁移

相关行动完成、阶段结束或工作集压力增大时，可归纳局部规律、失败条件与可复用方法。归纳产出新的 Claim / MethodExperienceRevision 或派生摘要，注明覆盖范围、遗漏、来源独立性、反例和推广限制；独立性未知时明确记录未知。

归纳不是新的独立原始证据。摘要逐项链接原始来源和命题版本；后续检查不能仅依赖摘要链。摘要、索引和工作上下文可重建，科研判断及决定的版本历史需要持久保存。维护使用 dirty/processed 水位与有界批次；摘要、checkpoint 和无变化 bookkeeping 不触发自身的新一轮归纳。

工作集可淘汰低相关缓存，原始来源按 task 的容量、许可与保留政策归档。获准删除来源时先登记受信 SourceTombstone（来源身份/版本、允许保留的 hash/provenance、原因、授权与删除状态）并使相关依赖不可作为当前支持，再由幂等删除处理器完成；崩溃后按该记录对账。该机制不删除事件、预算、Effect/ACK 历史或必要恢复入口；不能以缓存清理抹除反证。读取与回放区分有 tombstone 的 unavailable 和无记录的 missing/corrupt；历史快照也不能假称已删除正文仍可读取。

跨任务共享采用明确许可的只读版本包，保留来源、条件、反例、方法版本和访问限制。接收任务重新检查适用性；来源项目中的经验不自动推广。独立验证反馈不得回流到声称仍独立的比较输入。

10.3.7 角色、计费与领域预设

默认在 Lab 的正常调用中处理相关结果与记忆提议，无需新增常驻 Memory Agent。没有新信息或证据不足时允许空提议，不以写入量为成功目标。来源登记与执行回执由可信系统完成，不因模型未写判断而缺失。

耗时检索复用 evidence_retrieve；增量匹配、独立复核和可选归纳登记为 memory_match / memory_review / memory_consolidate。每种处理器同时提供权限、资源、恢复和终态；纯本地索引工作计量 CPU/时间，额外模型/工具调用另建 Effect 并共享任务预算。已有调用内的轻量解释不重复计费；维护不能把同一费用记两次，也不能占着外部许可等待子调用。

原有“每逻辑批次最多一个知识查询和一个记忆提议，两次尝试合计；每运行 12 查询 / 48 传输”仅保留为 §10.2 化合物工作流的可配置预设，不成为所有领域的内核规则。一般 task 显式配置读取、提议与维护预算及选择策略版本。provider、范围、条数和费用登记，source_call_id 由控制器认证；查询/提议在后续合法步骤使用，不增加该工作流的生成尝试次数。

科学解释更新不自动触发代码发布；改变检索机制、工作流或可执行方法时由 Meta 通过 ChangeEngine 处理。科研进展时钟只接受任务登记的真实进展，重复记忆、维护次数与归纳事件不制造进度或重新发放额度。

具体 actor、准入通道、Work owner 和 Wait 处置按 §2、§7–8；科学复核不能因 Meta credit 为零而被错误拒绝，也不借用修复额度绕过任务执行上限。memory_match 的纯本地部分不隐式调用模型/外部检索；需要这类效果时分别生成已登记 review/retrieve Work。最终停止状态优先于维护队列，规则见 §13.1。

10.3.8 机制验收与科研收益

首先验证引用、版本、条件、修订传播、实际交付和结果绑定；再测试关键证据与反证召回、条件/否定保真、复核延迟、未结工作恢复及成本。§17 的 SM01–SM20 为功能验收，不能用写入量、引用数或读到材料代替科学质量。

需要评估科研收益时按 §12 单独登记协议，比较有界原始历史、平面检索与结构化科研记忆。共同保留授权原始材料、工具和资源口径，所有整理/检索/复核均计费；不能隐藏基线证据。不同任务采用冻结的质量、复现、证明或证据覆盖终点，不强行压成统一分数。独立收益研究不成为 P4 工程修复发布的门槛。

11.3 生命周期与发布事务

detected → investigating → proposed → admitted → preparing → validating
  validating(pass) → ready_to_release → released → resuming → settled
  validating(fail/incomplete) → discarding_or_restoring → settled
  released/resuming(regression) → restoring → settled
  any stage(unknown effect / rollback failure) → recovery_required
  1. 调查保存真实复现、原始输出、失败日志和影响范围；先判断能否只重解析/重建视图。
  2. 准入检查授权、冻结要求、当前基准、预算和冲突；保存 checkpoint、恢复目标与续跑点。隔离工作区生成候选，活动版本保持不变。
  3. 优先在已有数据执行验收；仍需新数据时用最小样本。验证输出是带 effect、输入和产物 hash 的记录，不接受 Meta 的自然语言“测试通过”作为发布证据。
  4. 通过后在安全点以 expected active hash 做 CAS，原子登记 Release、版本指针、结果有效性投影、后继 Work 和 Continuation。CAS 失配保留候选与结果，重新评估适用性，不覆盖其他版本。
  5. 续跑从保存点执行：重解析、局部重算或继续下一个未完成步骤。第一次真实使用候选的派发事件证明生效；问题相关的后续成功结果才证明修复闭环完成。

有些能力必须在后续批次验收：先通过全部静态/历史检查，再建立有范围和预算限制的 provisional release，只有指定步骤可使用。窗口通过则在原版本上转为 accepted，不先恢复旧基线再重发同一版本；失败或信息不足则撤销试用版本。试用数据及其下游在通过前不得进入正式达标统计；失败时隔离受影响派生结果，原始输出与费用仍保留。

无需试用的改动通过小范围检查即可 accepted 并续跑，后续观察不会强制重启整轮任务。accepted 版本不因固定批数到期自动回退；出现可靠回归证据时发起恢复/修复事件。

11.4 代码、数据和协议的恢复

代码以不可变构建产物发布；依赖/导入检查、目标回归、启动兼容和版本回退必须可执行。运行进程不原地热改文件：组件可重载则在安全点切指针；需要重启则 supervisor 保存 checkpoint 后按新产物恢复。控制面变更也受同一版本与检查约束。

发布前失败只丢弃候选，不干扰活动版本；发布后失败恢复已知版本，并按依赖标记候选产生的错误/试用结果不可用于正式下游。回退不删除真实计算、费用和回执，不把错误旧结果恢复成有效证据。旧版本仍有原 bug 时相关步骤维持 blocked，Meta 可在剩余额度内修改下一候选。

数据迁移采用追加式或可恢复投影重建；未经预授权的不可逆 schema 破坏不属于默认修复。原始数据和旧事件不迁移覆盖。未知外部效果、恢复 CAS 失败或尚未终止的进程保留 recovery_required 和锁；数据证据无效但所有实际义务已结清时正常以 invalid/incomplete 结算，不能永久持锁。

协议变更先核对冻结要求和输入授权，再登记新版本与影响清单。复用须证明版本/输入兼容；存在不确定依赖就把该依赖闭包标记 needs_review，不能静默当作可复用。即使新协议整体更改全部输入而确需全量重算，也应由影响分析说明原因，而不是为了做默认基线对照。重算超预算时等待所缺授权或返回部分结果，不降低验收标准。

记忆策略、选择器、投影或 schema 变更的发布清单必须包含 MemoryRuntimeBinding 与兼容检查。切换前验证旧事件/科研版本、未决计划和实际读取清单能由新版本解释；迁移保存追加事件或可恢复投影。回退也需能读取运行期间已提交的新状态，或使用事先验收的兼容适配器；不支持时进入 recovery_required，不能强行用旧代码重解释未知 schema。回退机制版本不回滚已产生证据、费用、决定与判断历史；受候选机制影响的解释/摘要标记待复核，不自动继承旧 checked 状态。

11.6 开源 Codex harness 的自动修改与版本切换

本节定义必须实现的执行层自修复路径。 component=codex_runtime 与应用代码共用 Issue、ChangeSpec、AcceptanceSpec 和 Release，不建立绕过预算与验收的第二套自修改机制。Meta 在登记范围内从发现到续跑全程自主推进，无需用户逐次发出“改代码”“编译”“切换”指令；源码、构建工具或恢复器未就绪时报告具体依赖，不能声称已启用该能力。

主动巡检 / 错误或停滞证据
  → Meta 调查：定位 codex_runtime、冻结复现与修复范围
  → PatchExecutor：指定 fork 的隔离候选 → 修改源码 → 真实编译
  → AcceptanceGate：回归 + 接口/会话兼容 + 冻结要求 + 回退检查
  → RuntimeSupervisor：检查点 → 安全点切换 → 新进程握手
  → 当前 task 继续未完成步骤 → 真实结果认证 → Issue resolved

启动/握手/续跑回归  → 停止受影响派发 → 恢复已知产物与兼容检查点
无法确认外部效果    → recovery_required，对账后再续跑，不盲目重发

b. 自动发现、定位和准入

Inspector 按 §7 的周期与停滞机制独立读取 Codex 的事件流、调用输入输出、进程退出/超时、工具往返、压缩前后必要证据、重试和会话恢复记录。即使 CLI 返回成功，也可发现工具结果未进入上下文、必要约束丢失、重复调度或恢复后状态偏离。授权代码与确切版本可作为取证材料；发现缺少诊断能力时，可提出范围内的观测补丁并走同一验收路径。

Meta Worker 先区分领域错误、RSI 适配器错误、远端服务失败和 Codex harness 缺陷。只有证据支持修改执行层时，才创建 change_kind=codex_runtime_patch，列出复现输入、目标机制、预期行为、受影响角色/步骤、冻结验收和回退目标。规则可以直接登记提议，但不能跳过定位与准入；同一根因/版本重复告警合并到原 Issue，调查、失败候选和重试共用其预算与次数。

Codex 内部工具调用必须保留在 RSI 的资源与效果控制范围：科学工具、外部写操作经授权代理/MCP 网关进入内核 Effect 账本，使用稳定的任务/Work/逻辑调用标识去重。候选 runtime 不能获得绕过账本的执行通道；本地编辑、构建和测试也在对应隔离执行器内计费。无法关联或约束的副作用使该 runtime 契约不满足，不得靠 prompt 声称幂等或严格预算。

每次真实模型请求、自动重试和上下文压缩请求也必须通过登记的调用代理或 runtime 计量接口先预约，再关联子 Effect 并结算；最终一条 turn usage 只能用于核对，不能替代事前准入。无法观测/限制内部请求的 runtime 标为不满足该资源契约。长驻进程、会话和父 agent turn 是协调生命周期，不持有包住子请求的外部执行许可；父预算只转拨、不重复计费，许可按实际模型/工具请求持有和释放。模型返回工具请求后释放本次请求许可，再调度工具，因此单槽配置也能推进完整回合；未知子 Effect 按 §6 保留责任。

c. 隔离修改、真实编译和验收

  1. 固定当前 runtime binding、源码基线、复现材料、AcceptanceSpec、回退产物和兼容检查点；预留构建、验证、必要真实续跑和恢复资源。下载依赖、失败构建和测试调用均归属当前 Change，不重置任务总预算。
  2. PatchExecutor 创建只包含授权源码/输入的候选目录；Meta 修改代码并保存完整 patch。检查路径越界、符号链接、生成文件和依赖变化的实际影响，候选编辑/构建不得写活动源码、二进制、配置和会话目录。验证使用会话副本，checkpoint 保持不可变；活动 runtime 可按原契约追加自己的会话记录。构建脚本本身作为候选代码在隔离环境运行，不能获得发布注册表或 supervisor 写权限。
  3. 使用该 commit 登记的工具链、依赖锁与配方真实编译。保留命令/环境清单、退出状态、完整日志引用和每个产物 hash；缓存复用必须命中相同源码、工具链、依赖、配方及平台，不能把旧二进制当作新源码构建成功。
  4. 执行固定检查：原 bug 的可重现用例及相关正常路径；所选 exec/app-server 的请求、事件、结构化输出与工具往返；必要约束和证据保留；预算/权限与效果去重；会话恢复、停止/重启、旧产物可启动和回退检查。涉及远端调用的验证单独计费；fixture 只证明对应契约，不能替代真实续跑。
  5. 形成不可变 CandidateManifest 和验收记录。编译成功、--version 输出或 Meta 自述均不足以发布；必须通过预登记的必需检查。缺少平台工具链、接口兼容或恢复条件时保留具体 blocked/incomplete 原因，不默默改用系统 Codex。

d. 版本切换、会话恢复与当前任务续跑

切换由进程外的 RuntimeSupervisor 执行。Meta 即便运行在正在修复的 Codex 上，也只提交持久化请求；supervisor、授权检查、冻结验收入口和恢复资源由固定可信版本提供。构建和验证阶段保留可工作的 Meta 旧版本；若它本身故障，使用任务预先登记且兼容的已知版本继续诊断，缺少可用恢复路径则明确 blocked。

阶段 必须持久化的行为与完成条件
准备与静止 保存 RuntimeActivation、预期活动 hash、旧/新绑定、目标角色、checkpoint、续跑点和有界 deadline；停止目标作用域的新派发，允许无关工作继续。等待已有本地调用完成，或按契约取消并确认状态
效果对账 核对所有受影响 Effect 的 provider handle、原版本、费用和预约。终止 CLI 不等于取消远端调用；unknown 保留义务并阻止冲突续跑，不能用新进程/thread ID 重新执行同一工作
启动与检查 分配递增 runtime_generation，以确切 binary/config/adapter 启动候选，保存进程句柄并验证实际文件 hash、协议握手、会话加载及健康状态。仅允许登记探测，不提前派发生产工具调用；exec 模式探测通过后，每次后续调用仍校验同一绑定
提交活动绑定 在安全点 CAS 核对旧 release 和 activation 状态，原子追加 Release、角色绑定、激活序号与 Continuation。事务只提交本地事实和待执行意图，不声称 OS 进程操作属于数据库事务；崩溃由 activation 记录与进程查询对账
从断点继续 新调用使用新 binding 和 generation；已完成计算不重做，旧代结果按真实来源摄取，旧代命令不得改变当前状态。首个真实派发及问题相关后续成功结果同时留档，才能认证版本生效和 continuation=verified

旧进程的生产派发权限在切换时撤销，工具网关按 generation 校验；停止超时或无法确认旧进程是否仍可产生效果时，不启用冲突的新派发。每个 activation 的 deadline、启动/恢复次数和剩余额度必须有界；等待不能无限续租或刷新预算。

runtime_generation 按 run/branch/role 持久单调递增；启动重试和回退到同一旧 binary 也分配新代际，不能恢复旧 generation。工具/模型代理和控制面共同校验该代际，防止旧进程的迟到命令在回退后重新获得权限；旧事实的摄取仍使用原 Effect 身份和来源。

会话兼容采用明确的 resume_mode=native_compatible | validated_migration | reconstruct_from_checkpoint。原生恢复须有兼容测试；迁移在副本上执行并保留旧状态；不兼容时从 RSI 外部证据、任务状态和检查点构造新会话，保留必要约束、引用与未决义务，并重新认证实际交付。旧回执保留，但不能冒充新会话已读取材料；不重放已执行的模型/工具副作用。恢复材料不足则 blocked，不能静默丢失上下文后宣布续跑。

f. 完成证据

记录 trigger/inspection → issue → source diff → build → checks → activation/release → actual process binding → continuation → result，同时保留失败与回退链。只有实际启动了候选产物、后续调用使用该版本且原问题对应条件通过，才能报告“Codex harness 已修改并继续任务”；仅修改应用 prompt、写配置、生成 diff 或编译成功分别报告其实际进度。故障覆盖见 H01–H11；真实运行证明见 §17.3，收益结论仍按 §12 单独研究。

12. 可选的独立收益研究

研究问题是“整体任务效果/成本是否改善”，与工程问题“能否修好并继续”分开。需要研究时单独登记 ResearchExperimentSpec、明确预算和分析计划，不借工程修复自动启动对照实验。默认研究额度为零，P0–P4 不依赖研究 runner。

可选模式为同快照选择/生成比较 paired_snapshot、同检查点隔离完整运行 paired_rollout。完整运行只在研究问题需要时使用。每对固定 checkpoint、control/treatment 版本、seed、顺序与每臂预算；两臂的历史、记忆、候选身份、缓存、请求和随机流不共享可写状态，只共享冻结只读输入。

子运行不得递归申请配对研究、改父任务或写父发布注册表。runner 的协调步骤不占包住子调用的外部租约，每个子 effect 单独申请许可。共用执行容量时任务修复优先，研究等待或使用显式独立资源；不能因可选研究强制暂停主任务闭环。

失败、缺失、重试和全部费用保留；不只挑成功 pair、不依据结果补 seed。研究计划固定估计对象、指标/单位/分母、样本与缺失规则、停止条件和分析器。无正式推断方案只报告描述性差异，不宣称统计显著或因果收益。父停止传播到子运行，在途结果对账后才能结清研究义务。

ScientificInvestigation 是完成原 task 的科研行动，§10.3 记忆机制的功能验收不依赖本节的对照 runner。若单独评价记忆收益，应冻结来源访问、工具、模型、总资源和任务终点，比较有界原始历史、平面检索与结构化记忆；整理、检索与检查成本全部计入，不通过隐藏基线证据制造收益。

13. 停止、收尾与恢复

13.1 停止新工作

task 的冻结完成判据满足、预算/时长耗尽、用户停止、不可恢复错误或有界停滞处理失败时进入 finalizing。停止新 Lab、发现、变更，以及新的科研解释/归纳/外部检索 Effect；已排队 memory_review / memory_consolidate 不因不叫 lab_step 而绕过停止。继续幂等摄取已承诺的在途结果、确定性失效标记、待处理状态持久化和必要恢复；不为清空记忆队列新增模型/工具调用。

处理顺序：摄取已落盘结果 → 对账未知效果 → 撤销未验收试用版本/完成必要恢复 → 结算可判定变更与 Continuation → 处理未决 Wait 或记录资源不足 → 验证当前结果和任务完成条件 → 输出义务与预算总账。已 accepted 的修复不无条件退回旧基线。

收尾不额外启动整轮对照，也不偷偷增加评价来凑达标数或验收样本。合法在途预约按停止策略处理。对于冻结了至少 100 个达标 compound 要求的任务，若有效达标数少于 100，即使停止原因是预算耗尽或修复完成，也不能标记科学任务成功；其他领域使用各自冻结完成判据。

13.2 报告相互独立的状态

stop_reason = goal_met | compute_budget | token_budget | wall_time | user_stop | stalled | error
task_status = succeeded | partial | blocked | failed
settlement_status = settled | blocked_external | resource_exhausted | failed
work_status = empty | pending_queued | parked_dependencies | unresolved_effects

settled 表示外部效果和恢复义务已结清，不表示所有 Issue 已解决或任务达标。报告必须列出未决对象、原因、负责处理器和可恢复动作。

科研记忆报告使用 scientific_memory_report = {scope, as_of_seq, flags[], pending_object_refs[]}；flags 可同时包含 review_pending, source_unavailable, maintenance_deferred, support_check_pending。空集合仅表示该范围没有已登记的对应未决项，不宣称所有判断均正确或已审阅。最后一批未解释结果保留 awaiting_review，未完成支持检查不写成 checked；冻结完成条件要求的复核未完成时，task 不能 succeeded。该报告不重定义 task_status 或 settlement_status。

13.3 重启与旧轨迹迁移

启动校验配置、冻结要求 hash、实际 runtime/memory binding、schema、blob 与事件/投影一致性。先摄取已落盘回执，恢复 unknown、版本及依赖的持久状态并安排有界对账；未决效果保留，仅阻塞冲突动作和其占用许可，不要求所有 unknown 已解决才能继续独立本地恢复与报告。prepared outbox 重新通过 §6 TX2，不在启动扫描中直接重发。恢复中断 Step/Batch 与科研义务后，普通 Lab、科研复核/归纳和新检索仅在非 finalizing 且通过依赖/权限/预算门槛时派发；已承诺的必要对账、取消、回退与恢复可在 finalizing 中按登记权限和恢复预留执行。预算、问题尝试次数、wait_epoch、身份预约和进度不重置。

已有历史默认只读保留。接入新编排使用明确 child/checkpoint：冻结父边界/哈希，验证父 prefix，按 (parent_checkpoint_hash, target_schema_version, migration_version) 幂等追加迁移事件，使用新 branch namespace。旧等待映射为带原原因的 Wait 并获得一次 legacy_wait_reassessment；不宣称新原因已验证。旧活动试验由兼容恢复器结清，unknown 先对账。所有新执行、重审与费用位于新边界之后。

记忆恢复保留来源版本、科学问题、判断关系、实际交付清单、未结研究行动、复核/匹配水位和 Wait epoch；不重新执行已确定的外部动作。迁移旧自由文本时保留原文和来源，推断出的结构化对象标为待检查；不能伪造旧调用已读引用、历史支持检查或事前检验承诺。跨任务导入使用明确许可的只读版本包，目标任务重查适用性。

有合法 SourceTombstone 的来源缺失按 unavailable 恢复，其依赖动作继续受阻，无关工作可以恢复；没有该记录的丢失、hash 不符或损坏报告完整性错误，不自动补写 tombstone 掩盖。恢复的是历史交付事实，不把旧 call 的 actual_read_manifest 转授给新 call 或新会话；新的科学提议必须引用该调用实际重新交付的来源。同一已完成 call 的幂等结果重放使用原记录，不重复调用或结算。

可选研究启用后另测分支隔离、失败 pair 保留、禁止递归研究、预算不增发及停止传播。研究测试不加入默认 P4 的前置依赖。

17.3 P4 真实案例留档

每个案例保存首次可见线索及巡检触发、是否有 Lab/用户报告、实际检查与取证范围、问题出现时的输入/错误与 checkpoint、Meta 的原因调查、实际 patch/构建 hash、小范围验收记录、冻结要求前后 hash、发布事件、真实续跑点和后续结果、复用/重算清单及全部成本。缺任何关键环节则报告尚未验证，不能用合成成功响应填充。

P4 按 §16 分别登记通用闭环与 Codex 自修改子项。五类路径的受控覆盖由 P3 验收；P4 明确标注真实任务实际覆盖哪几类，不把一例修复泛化为所有场景的效果证明。无修复机会的 pilot 保留其真实结果，相关子项仍待验证；不为了通过而擅自改目标或增加预算。

Codex 案例额外留存实际 fork/commit、源码 diff、工具链/依赖/构建日志、候选 binary/config/adapter hash、兼容报告、旧/新会话与 generation、activation 的前后状态、真实首用和后续结果。另用受控失败演练证明独立 supervisor 可回退；故障注入与自然问题分别标注。只运行预制的新二进制或人工手动替换版本，不构成 Meta 自动修改、编译和切换能力的完整证据。

“主动检测能力已验证”另需至少一个未由 Lab/用户预先报告具体故障、由 Meta 独立发现并完成取证的真实案例，以及 O12 的检测质量报告。外部告知问题后成功修复可以证明修复闭环，不能代替自主检测证据。

18. 设计完成与实施完成的区别

本次交付是版本 2.1 的系统设计。实施完成必须具备：三层边界可检查；领域中立入口；持久效果和预算正确；任务冻结要求可执行；Meta 独立巡检、主动取证和持续调查可运行；在授权内能实际修改；五类局部验收/恢复路径，包含开源 Codex harness 的自动源码修改、真实编译验收、版本切换、当前任务续跑与失败回退；受影响重算与原始数据复用；明确未决义务报告。Codex 自修改是主闭环实现要求，不后置到可选收益研究。

核心实施验收是系统实际修好了问题，并成功继续任务。 配对收益实验不属于这条闭环的必需条件；科学任务的最终完成条件也不会因修复验收通过而放宽。
